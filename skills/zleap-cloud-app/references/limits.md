# 平台边界与限制

这一页汇总**当前平台开放到什么程度**，以及各种硬性数值限制。

> **为什么要有这一页**（提示）
>
> 了解边界能省下大量试错时间。很多「为什么不行」的答案是「平台还没开放」或「部署没配置」，
> 而不是你的配置错了。

本页数值来自服务端 Go 代码、Cloud SDK 与控制台源码。标注「部署可调」的是默认值，
具体部署可能改过；SDK 中 `await zl.cloud.os.getCapabilities()` 返回的 `limits` 是当前会话与宿主协商的实际值。

## 能力开放状态

| 能力                               | 状态          | 说明                                                                                                                                        |
| ---------------------------------- | ------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| 云数据库                           | ✅ 开放       | 集合按 Manifest 自动创建；文档、索引、备份恢复                                                                                              |
| 文件存储                           | ✅ 开放       | 分块上传、下载、条件覆盖、软删除                                                                                                            |
| 日志                               | ✅ 开放       | 查询 + 追尾；生产环境只读，发布者可见全部调用日志                                                                                           |
| 云函数 / 后台能力                  | ⚠️ 视部署而定 | 需要部署了函数运行环境；还需就绪的签名发布（带后台能力的版本上传时由平台自动签名，安装 / 切换版本 / 授权时自动绑定）并授权                  |
| 发布候选与签名                     | ✅ 自动       | 平台在上传时自动签发开发版本、首次发布时自动签发生产发布，没有手动步骤。签名需部署配置发布信任策略，未配置时发布报「发布信任策略尚未配置…」 |
| 生产环境数据 / 文件管理（控制台）  | ⚠️ 视部署而定 | 生产开放后可在控制台查看和修改（页面有影响范围提示）                                                                                        |
| 应用中心 · 更新 / 回滚             | ✅ 开放       | 有升级预检；只切换当前用户自己的安装                                                                                                        |
| 控制台 · 发布为线上版本            | ✅ 开放       | 控制台「发布 → 版本管理」；发布后全企业可见，无审核步骤；回退 = 把旧版本再发布一次                                                          |
| 生产准备（首次发布带云资源的版本） | ⚠️ 视部署而定 | 平台自动完成生产环境、生产发布、生产门禁、生产库与集合；发布信任配置未就绪时没有生产入口                                                    |
| 应用成员（管理员 / 开发者）        | ✅ 开放       | 控制台「团队」→「成员」，见 [成员管理](console-members.md)                                                                                    |
| 使用其他成员上传的开发版本         | ✅ 开放       | 版本可见性为 `members`；成员在「版本管理」里用「切换到此版本」切换（只影响自己）                                                            |
| 纯后台（`headless`）应用           | ❌ 基本不可用 | 声明云函数等即「运行环境未开放」，请用 `both`                                                                                               |
| `agent.interaction`                | ❌ 未开放     | 声明会导致应用无法安装                                                                                                                      |
| 集合分区 `app`                     | ❌ 未开放     | Manifest 写 `partition: "app"` 会被拒绝                                                                                                     |

## 未实现的 SDK 功能

以下调用会**明确抛出**错误（一般是 `UNSUPPORTED_OPERATION`；宿主没协商到 `app-execution/1` 时是 `BACKGROUND_CAPABILITY_UNAVAILABLE`），不会静默失败：

| 功能                                             | 说明                                                                                                                                                         |
| ------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 数据库事务 `runTransaction()`                    | 不支持                                                                                                                                                       |
| 按条件批量写 `where(...).update()` / `.remove()` | 只能按文档逐条写                                                                                                                                             |
| 游标分页 `query.after()`                         | 用 `skip` + `limit` 分页                                                                                                                                     |
| 临时文件链接 `getTempFileURL()`                  | 用 `downloadFile()`                                                                                                                                          |
| 握手未声明的协议 profile 或运算符                | 宿主未协商的能力；`app-execution/1` 缺失时 `callFunction` / `capabilities.invoke` 抛 `BACKGROUND_CAPABILITY_UNAVAILABLE`，其余情况抛 `UNSUPPORTED_OPERATION` |

另外，iframe 内的 SDK **不能跨应用调用**其他应用的能力。

## 数值限制

### 应用包

| 项                   | 限制                                       |
| -------------------- | ------------------------------------------ |
| ZIP 大小             | ≤ **20 MiB**                               |
| 解压后总大小         | ≤ **80 MiB**                               |
| 单文件大小           | ≤ **20 MiB**                               |
| `manifest.json` 大小 | ≤ **1 MiB**                                |
| 文件条目数           | **1–2000**                                 |
| 压缩比（单文件）     | ≤ **100**                                  |
| 路径长度             | ≤ **512**                                  |
| 必需文件             | `manifest.json`、非空 `LICENSE`、入口 HTML |

打包与排除规则见 [Manifest · 打包规则](manifest.md#打包规则)。

### Manifest

| 项            | 限制                                 |
| ------------- | ------------------------------------ |
| 嵌套深度      | ≤ **24**                             |
| 节点总数      | ≤ **16384**                          |
| `appid`       | `zl` + 16 位小写十六进制，由平台生成 |
| `name`        | 1–128 位                             |
| `description` | ≤ 2000 位                            |
| `icon`        | ≤ 512 位                             |
| `version`     | ≤ 32 位（语义化版本）                |

### 云函数与 Provider

| 项                      | 限制         | 默认 |
| ----------------------- | ------------ | ---- |
| 函数数量                | ≤ **32**     | —    |
| Provider 数量           | ≤ **64**     | —    |
| `timeout_seconds`       | 1–**300**    | 30   |
| `memory_mb`             | 64–**4096**  | 512  |
| 重试次数 `max_attempts` | 1–**3**      | 1    |
| 运行时                  | `node-lts/1` | —    |

### 能力

| 项                               | 限制                                    |
| -------------------------------- | --------------------------------------- |
| `requires` 数量                  | ≤ 64                                    |
| `provides` 数量                  | ≤ 64                                    |
| `reason` 长度                    | 1–512 位                                |
| `input_schema` / `output_schema` | 各 ≤ **64 KiB**，深度 ≤ 16，节点 ≤ 4096 |
| 能力调用输入 `input`             | ≤ **64 KiB**                            |

### 数据集合

| 项                  | 限制                                                                    |
| ------------------- | ----------------------------------------------------------------------- |
| Manifest 声明集合数 | ≤ **64**                                                                |
| 每环境集合数        | ≤ 100（部署可调）                                                       |
| 集合键              | `^[a-z][a-z0-9_]{0,63}$`，禁用 `sys_` / `ac_` / `t_` 前缀               |
| 集合 Schema         | 每对象 ≤ 256 个属性，嵌套 ≤ 16 层，`enum` 1–100 个值；整体定义 ≤ 32 KiB |
| 记录规则            | ≤ 2048 字符，≤ 64 个节点，嵌套 ≤ 8 层                                   |
| 字段名              | `^[A-Za-z][A-Za-z0-9_]{0,63}$`                                          |
| 文档大小            | ≤ **256 KiB**                                                           |
| 文档嵌套 / 路径数   | 深度 ≤ 16，字段路径 ≤ 256                                               |
| 数值                | 绝对值 ≤ 2^53−1（9007199254740991）                                     |
| 文档键              | ≤ **128** 字节，不能含控制字符                                          |
| 索引数量            | 每集合 ≤ **4**                                                          |
| 可建索引字段        | strict 集合中必填、非空的顶层标量；字符串需 `maxLength` ≤ **191**       |
| 备份单次上限        | **1000** 条记录 / **8 MiB**                                             |

### 数据配额（部署可调）

| 范围                 | 文档数 | 字节数  |
| -------------------- | ------ | ------- |
| 每个应用             | 100000 | 512 MiB |
| 每个环境             | 50000  | 256 MiB |
| 每个数据绑定（每人） | 10000  | 64 MiB  |

超出返回 `RESOURCE_EXHAUSTED`。

### 数据库操作

| 项                    | 限制                                                                                                     |
| --------------------- | -------------------------------------------------------------------------------------------------------- |
| 分页大小 `limit`      | 1–**100**，默认 20                                                                                       |
| 偏移 `skip`           | 0–**1000**                                                                                               |
| 排序字段 `orderBy`    | ≤ **4**                                                                                                  |
| `watch` 单次文档数    | ≤ **100**                                                                                                |
| 请求体                | ≤ **256 KiB**                                                                                            |
| 响应                  | ≤ **1 MiB**                                                                                              |
| 查询过滤              | 深度 ≤ 8，节点 ≤ 64，`and`/`or` 子条件 1–20                                                              |
| `in` / `nin` 数组长度 | 1–**100**                                                                                                |
| 字段更新操作          | 单次 ≤ 256 个                                                                                            |
| 单次查询扫描上限      | 无索引 10000 条，走索引 200000 条（部署可调）                                                            |
| 单应用并发数据请求    | 同时 **8** 个（部署可调），超出返回 `APP_RATE_LIMITED`                                                   |
| 每人数据请求频率      | 每个登录用户每分钟数百次（部署设置，常见 300–500；应用数据读写、文件、执行通道合计），超出返回 `APP_RATE_LIMITED` |
| 同一出口 IP 总闸      | 每人额度的 **10** 倍 / 分钟（同一公司网络出口的所有人合计），超出返回 `APP_RATE_LIMITED`                  |
| 单个窗口在途请求      | 同时 **8** 个，超出 SDK 直接抛 `RESOURCE_EXHAUSTED`（不发请求）；批量写请自己限制并发，例如每次最多 6 个 |
| 操作编号首次使用窗口  | **300** 秒（编号里的时间戳与服务端时间差）                                                               |
| 操作回执保留          | **24** 小时                                                                                              |

查询扫描超过上限时返回 `INDEX_REQUIRED`，`message` 里会带上具体上限：缺索引时为常用查询字段建索引；
已经走了索引仍超限时，缩小筛选范围。

### 文件存储

| 项                   | 限制        |
| -------------------- | ----------- |
| 单文件大小           | ≤ **4 MiB** |
| 分块大小             | **256 KiB** |
| 单文件分块数         | ≤ **16**    |
| 并行上传分块         | ≤ **2**     |
| 每个数据空间存储配额 | 64 MiB      |
| 每个应用存储配额     | 256 MiB     |

### 触发器与事件

| 项             | 限制                                  |
| -------------- | ------------------------------------- |
| 定时触发器     | ≤ **32**                              |
| 事件触发器     | ≤ **32**                              |
| `publishes`    | ≤ 64                                  |
| `subscribes`   | ≤ 64                                  |
| 触发器运行参数 | ≤ **8 KiB** 的 JSON 对象              |
| 事件名         | `^[a-z][a-z0-9_.]{0,63}$`             |
| 策略           | 仅 `overlap: forbid`、`misfire: skip` |

### 执行

| 项                      | 限制                                         |
| ----------------------- | -------------------------------------------- |
| `max_concurrency`       | 1–**64**，默认 1                             |
| 能力调用 `input`        | ≤ **64 KiB**                                 |
| `waitSeconds`           | 0–**25**                                     |
| `jobs.wait` 超时        | 0–**300** 秒，默认 25                        |
| `jobs.wait` 轮询间隔    | 100–**5000** 毫秒，默认 500                  |
| `callFunction` 同步等待 | 25 秒，未结束抛 `CALL_TIMEOUT`（带 `jobId`） |

### Agent（`os.agent.complete` / 页面 `POST /agents/complete`）

| 项                        | 限制                                                                                                                      |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| 输出 `output` / `text`    | ≤ **8000** 字符（服务端截断）                                                                                             |
| `timeout_ms`              | 整次调用上限（含重连与契约重试），默认 **20000** 毫秒；服务端整次最多 **110** 秒，超时返回 40049（`data.reason=timeout`） |
| 契约模式 `max_retries`    | 不含首轮；建议 0–1，每次重试再调一次模型                                                                                  |
| 页面 `api.fetch` 单次调用 | 服务端最多等 **120** 秒；SDK 不设超时，可传 `signal`                                                                      |

输入长度以你在能力 `input_schema` 里声明的为准；`copilot-studio` 示例用的是 `input` ≤ 16000、`system` ≤ 4000，
平台侧的输入上限**未验证**。

### 日志

| 项                       | 限制                                                                                   |
| ------------------------ | -------------------------------------------------------------------------------------- |
| 控制台单次显示上限       | **1000** 条                                                                            |
| 控制台追尾轮询间隔       | **3** 秒                                                                               |
| `zleap-app runtime-logs` | 当前用户/应用最近 24 小时，最多 200 条页面结构化错误；另附本人云函数日志（默认 50 条） |

### 应用窗口与 SDK 通道

| 项             | 限制                                                        |
| -------------- | ----------------------------------------------------------- |
| 并发请求       | ≤ **8**                                                     |
| 单请求超时     | **30** 秒（读超时 `CALL_TIMEOUT`，写超时 `COMMIT_UNKNOWN`） |
| 握手超时       | **15** 秒                                                   |
| 单会话请求编号 | ≤ 4096 个                                                   |

### 开发工具（`zleap-app`）

| 项                       | 限制                                                                                                 |
| ------------------------ | ---------------------------------------------------------------------------------------------------- |
| 开发会话                 | 访问凭据 **30 分钟**，自动续期，自首次授权起最长 **30 天**；只限一个 `appid`；`auth logout` 立即撤销 |
| 浏览器验收               | 单次 ≤ 128 步，总计 ≤ 5 分钟                                                                         |
| `workspace.files` 单目录 | ≤ 500 个文件、100 个直接子目录                                                                       |
| `workspace.files` 移动   | 每次 ≤ 100 个文件；目录句柄最多保留 1 小时                                                           |

## 平台不做什么

这些是**有意的设计选择**，不是功能缺失：

| 平台不做                           | 原因 / 替代                                   |
| ---------------------------------- | --------------------------------------------- |
| 把接口缺失当成空目录               | 会让故障看起来像「没有数据」                  |
| 显示或执行「假更新」               | 会误导用户                                    |
| 在结果不明时猜测成功或失败         | 返回 `COMMIT_UNKNOWN`，用原操作编号查询       |
| 自动重试写操作                     | 除非 provider 声明 `retry.mode: "idempotent"` |
| 撤销授权时回滚已提交的修改         | 只阻止后续步骤                                |
| 安装应用即启动后台任务             | `on_install` 固定为 `disabled`                |
| 自动迁移数据                       | 已建集合的 Schema、分区不随新版本改变         |
| 允许 SDK 跨应用调用                | 权限边界                                      |
| 让应用自行建立网络连接             | 沙箱 iframe 为 `connect-src 'none'`           |
| 让云函数拿到数据库凭据或用户 token | 最小权限                                      |

## 已知会导致「应用不可安装」的配置

结构合法但被运行能力检查拒绝时，`zleap-app check` 不通过，应用中心无法安装打开：

| #   | 配置                                                                                                                                                          | 原因码                 | 修法                      |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------- | ------------------------- |
| 1   | `schema` 不是 `zleap.app/2`                                                                                                                                   | `MANIFEST_UNSUPPORTED` | 升级 Manifest             |
| 2   | `runtime.ui.type` 为 `builtin`                                                                                                                                | `RUNTIME_UNAVAILABLE`  | 改为 `iframe`             |
| 3   | 无 `ui` 的 `backend` 含函数、`managed_function` 或未知 `builtin`                                                                                              | `RUNTIME_UNAVAILABLE`  | 加前台界面，改为 `both`   |
| 4   | `runtime.ui.providers` 非空                                                                                                                                   | `FEATURE_UNAVAILABLE`  | 删掉 `providers`          |
| 5   | `provides` 含 `execution: "foreground"`                                                                                                                       | `FEATURE_UNAVAILABLE`  | 改 `headless` 或删除      |
| 6   | 声明了 `agent.interaction`                                                                                                                                    | `FEATURE_UNAVAILABLE`  | 删掉                      |
| 7   | `requires` 含开放清单外的非可选能力                                                                                                                           | `FEATURE_UNAVAILABLE`  | 删掉或设 `optional: true` |
| 8   | 没有 `backend` 却非可选地申请 `os.agent.complete`                                                                                                             | `FEATURE_UNAVAILABLE`  | 加 `backend` 或删掉       |
| 9   | `host_api.profile` 不是 `app-runtime/2`，或 `requires` 含 `clipboard.write`、`workspace.files`、`workspace.images.read`、`credentials.use`、`user.*` 之外的值 | `FEATURE_UNAVAILABLE`  | 改正或删掉                |

开放能力清单见 [Manifest · 目前开放的能力](manifest.md#目前开放的能力)。
可安装的参考实现：`examples/app-cloud/copilot-studio`（`both` 形态）。

## 依赖部署的能力

以下能力**取决于部署是否配置**，不是你的代码能决定的。遇到时不要用回退数据冒充成功：

| 项目         | 未配置时的表现                                                                        |
| ------------ | ------------------------------------------------------------------------------------- |
| 函数运行环境 | 控制台云函数显示 `RUNTIME_UNAVAILABLE · 函数执行 Provider 尚未开放。`                 |
| 发布信任策略 | 发布签名失败，报「发布信任策略尚未配置，或发布者密钥不可用、已撤销或已过期。」        |
| 生产发布     | 发布信任配置未就绪时控制台不出现生产入口；发布接口报 `PRODUCTION_RELEASE_UNAVAILABLE` |
| 数据服务     | `RESOURCE_NOT_READY` / `DATA_SERVICE_UNAVAILABLE`                                     |

> **关于「能跑」的判断标准**（注意）
>
> `zleap-app check` 或 `prepare` 成功都只代表静态检查与资源准备通过（`runtime_test=not_checked`），
> 不代表数据读写已经可用。平台的原则是：**明确失败优于虚假成功**。
