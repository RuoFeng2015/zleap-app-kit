# 安装与卸载

这一篇讲：安装确认里展示什么、**安装即授权**意味着什么、卸载会怎样、如何更新 / 回滚，以及应用窗口里的两个授权入口。

## 安装应用

### 操作步骤

1. 在「**发现**」或「**我的应用**」里点应用卡片，进入 详情页（文档站 ./detail）。
2. 点右上角主按钮「**安装**」。
3. 在确认框里核对权限并确认。

> **能装哪个版本**（提示）
>
> 「安装」装的是目录里该应用的**当前版本**：
>
> - 已发布过线上版本时，装的就是**线上版本**；
> - 还没发布过线上版本时，只有应用成员能安装和使用开发版本。
>
> 创建了但还没上传过任何版本的应用是草稿，不会出现在应用中心。
>
> 想装其他版本，先装上，再用「更新」或 CLI `update` 切换；应用成员也可以在控制台「版本管理」里用「**切换到此版本**」直接切换到某个开发版本（只影响自己桌面上的应用）。

### 安装确认框

> **安装"应用名"？**
>
> 安装到你的个人应用。安装不授予 Agent 调用权限，也不会自动启用后台任务。

说明下方逐行列出这个版本声明的权限，文案来自 `apps.json` 的 `apps.installPermissions.*`：

| 声明的能力                                   | 确认框里的文案                                                   |
| -------------------------------------------- | ---------------------------------------------------------------- |
| `cloud.database.read`                        | 读取本应用数据库                                                 |
| `cloud.database.write`                       | 写入本应用数据库                                                 |
| `cloud.storage.read`                         | 读取本应用存储文件                                               |
| `cloud.storage.write`                        | 写入本应用存储文件                                               |
| `storage.kv`                                 | 读写本应用设置                                                   |
| `space.read`                                 | 读取本应用数据空间                                               |
| `space.write`                                | 写入本应用数据空间                                               |
| `notify.send`                                | 发送应用通知                                                     |
| `clipboard.write`                            | 写入剪贴板                                                       |
| `workspace.files`                            | 读取及整理选定空间文件夹内的文件                                 |
| `workspace.images.read`                      | 显示原始 ID（暂无中文文案）：读取选定文件夹里的图片              |
| `user.profile` / `user.phone` / `user.email` | 使用时可能申请你的头像和昵称 / 手机号 / 邮箱（由你决定是否同意） |
| `os.agent.complete`                          | 调用已授权的助手能力                                             |

列表的来源是 Manifest 的 `capabilities`、`storage.capabilities`、`host_api.requires` 和 `runtime.capabilities.requires[].id`。
没有对应文案的能力（例如 `os.todos.read`）直接显示能力 ID。

### 安装即授权

> **点「确认」就等于授权**（注意）
>
> 安装时，服务端在**同一个事务**里把这个**固定版本**声明的上述权限一次性授予给你（`appinstallation/grants.go`）：
>
> - `cloud.database.*` / `cloud.storage.*` 会同时授予 **dev 和 prod** 两个数据域；
> - 授权绑定「你 × 这个安装 × 这个版本」；授权写入失败则整个安装回滚。
>
> CLI 的 `zleap-app install APP_ID` 语义相同。单独的 `check` / `publish` 不授予任何权限。

安装授权**不等于**一切就绪：

| 安装之后                | 还需要什么                                                                                                                                               |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 云数据库 / 存储能读写   | 云环境、数据库、集合已就绪（声明了集合的应用安装时会自动创建开发环境并开通，通常一分钟内），且仍要过数据面的 ACL 检查                                    |
| 后台任务 / 云函数会运行 | **不会自动启动**：安装时后台能力被预置为「停用」，需要在应用窗口「权限」里允许后台运行；绑定就绪发布由平台自动完成（上传自动签名，缺签时当场补签并绑定） |
| 定时任务                | 开发者开放了的定时任务，在「权限」里对应后台能力下面有开关，自己决定开不开；时间和内容由开发者定                                                         |
| Agent 能调用你的应用    | 安装不授予 Agent 调用权限                                                                                                                                |

所以「装上了但读不到数据」通常是云资源还没准备好，而不是没授权。排查顺序见 [从开发到上线](dev-to-production.md)。

### 安装过程与结果

确认后界面依次显示：

1. 「**正在核对安装状态…**」——提交后重新读取安装列表并同步桌面；
2. 「**应用已安装，可在启动台打开。**」——核对一致。

| 情况     | 提示                                                                         |
| -------- | ---------------------------------------------------------------------------- |
| 结果不明 | 「尚未确认操作结果」——请先重新读取安装状态，**不要重复提交**；点「检查结果」 |
| 被拒绝   | 「操作已被拒绝」                                                             |
| 打开失败 | 「暂时无法打开应用，请刷新后重试。」                                         |

服务端常见拒绝原因：「该 APP 已在此空间安装」、「当前应用版本不可安装」（当前版本已停用或不可见）、「APP id=… 不存在或已停用」。

链接里带了空间范围参数时，会提示：

> 「此链接指定了尚未支持的安装范围。应用中心目前只管理个人安装，不会改为个人范围执行。」

并给出「查看个人应用」按钮。应用中心只管理**个人安装**。

## 卸载应用

### 操作步骤

1. 进入应用的 详情页（文档站 ./detail）（从「我的应用」点卡片即可）。
2. 点主按钮旁的「**卸载**」。
3. 确认。

> **卸载"应用名"？**
>
> 移除你的应用安装和桌面入口。应用数据会保留，不会删除。

系统核心 / 系统基础应用（tier `os-core` / `os-base`）、空间站点没有「卸载」按钮。

> **卸载完成的提示**（提示）
>
> 卸载核对完成后，提示「**应用已卸载，授权已撤销，应用数据会保留。**」

### 卸载会做什么

依据 `appinstallation/write.go` 的 `Uninstall`：

| 会撤销 / 停用                                 | 会保留                                   |
| --------------------------------------------- | ---------------------------------------- |
| 安装记录（状态变为 uninstalled）、桌面入口    | 应用数据（Cloud 数据库、存储、托管设置） |
| 运行会话、Cloud 会话、文件票据、交互会话      | 你上传的应用包和版本                     |
| **全部权限授权**（安装授予的和你后来勾选的）  |                                          |
| 后台能力激活（定时任务 / 云函数不再为你运行） |                                          |

重新安装会重新授予该版本声明的权限；后台能力仍需重新勾选。

> **卸载 ≠ 清理数据**（危险）
>
> 卸载不会删除数据，也没有「卸载并清空数据」的选项。不要指望用卸载重装来「重置」测试数据。

## 更新与回滚

### 自动跟随线上版本

不需要使用者手动更新：

- 成员在控制台「版本管理」里发布新版本（或回退到旧版本）后，**不是应用成员的使用者下次打开应用时**，
  宿主发现线上版本和自己装的不一样，会先把安装切到线上版本，显示「**正在更新到最新版本…**」，再加载应用；
- **已经开着的窗口不会立刻被打断**：宿主每 20 秒检查一次更新，先通过 `zl.app.getUpdateManager()` 通知应用，应用可以用 `onUpdateReady` 提示用户、调用 `applyUpdate()` 立即切换，见 版本更新与授权登录（文档站 /reference/app-runtime#版本更新）；
- 但宽限期只有 **24 小时**：新线上版本发布 24 小时后，**非成员**的旧窗口会被强制切换并重新加载，提示「**这个版本已超过 24 小时的使用期限，正在更新到最新版本…**」；
- 应用成员（管理员 / 开发者）**从不被自动切换**，他们在控制台「版本管理」里用「**切换到此版本**」自己选版本（只影响自己，含同事未发布的开发版本）。

下面的「更新」页、回滚和 CLI 切换照常可用。

### 在应用中心更新

1. 左侧导航进入「**更新**」。列表里每项写成「已安装 1.0.0 → 最新 1.1.0」。
2. 点「**更新**」，弹出「**更新到 1.1.0？**」确认框。
3. 确认框里会显示：
   - 正常时：「**升级后授权按能力自动延续**」——「权限未变或收窄的能力会继承你此前的授权；只有新增能力或扩大的数据范围才会要求你重新确认。运行会话与托管文件票据会重建。」
   - 预检阻断（「**预检不通过，无法升级**」）或警告（「**可以升级，但请注意**」），见下表。
4. 点「更新」。成功后提示「{应用} 已更新到 {版本}」，并列出「N 项后台能力授权已延续」「N 项授权需要重新确认后才能继续调用」「N 项能力在新版本中已移除，授权已撤销」。

> **「更新」列表为空？**（提示）
>
> 「更新」页用「发现」目录里已读到的版本做比较。如果明知有新版本却没出现，先在「发现」里搜到这个应用，再回到「更新」。

**预检结果**（`appversion/read.go`、`continuity.go`）：

| 代码                                        | 类型 | 界面文案                                                       |
| ------------------------------------------- | ---- | -------------------------------------------------------------- |
| `RELEASE_NOT_PUBLISHED`                     | 阻断 | 该版本尚未签发发布：切过去后云函数等后台能力无法激活。         |
| `COLLECTION_PARTITION_IMMUTABLE`            | 阻断 | 集合作用域（私有/共享）不可变更，开通会被数据面拒绝。          |
| `COLLECTION_SCHEMA_NOT_APPLIED`             | 警告 | 已存在集合的结构不会更新，新版本若依赖新字段可能被旧约束拒绝。 |
| `COLLECTION_NO_LONGER_DECLARED`             | 警告 | 新版本不再声明该集合；已建集合不会被删除，数据仍在。           |
| `CAPABILITY_CONSENT_REQUIRED`               | 警告 | 这些能力的权限变宽，需要你重新确认后才能继续调用。             |
| `CONTINUITY_UNKNOWN` / `DATA_DELTA_UNKNOWN` | 警告 | 旧版本清单不可解析…… / 数据声明无法比对，请人工确认集合变更。  |

另外，「更新」页在调用预检之前还会读取当前账号可切换的版本列表。如果目标版本不在列表里
（已下架、不可见，或官方资源版本状态异常），前端会直接阻止升级：

| 代码                    | 类型 | 界面文案                                   |
| ----------------------- | ---- | ------------------------------------------ |
| `VERSION_NOT_AVAILABLE` | 阻断 | 该版本当前不可切换（可能已下架或不可见）。 |

`VERSION_NOT_AVAILABLE` 是**前端版本列表的阻断**（`upgrade-model.ts` 的 `resolveUpgradeBlock`，界面 key 为 `upgradeBlockedUnavailable`），
不会出现在服务端预检结果里。遇到时先在「发现」里重新搜到该应用（刷新目录），或让发布者确认该版本仍然可见。

> **目标版本必须有「就绪」的发布**（注意）
>
> 应用中心前端还会检查目标版本的 `release_id`：为空时显示「该版本尚未发布（release）。切过去后云函数等后台能力无法激活，请先由发布者签发该版本。」并阻止升级——包括没有云函数的纯前端应用（服务端预检对纯前端应用其实不拦，这是前后端判定不一致）。
> 带云函数 / 后台能力的版本上传时平台已自动签名；切换版本、重新保存权限或允许后台运行时，平台会自动补签并绑定，正常不需要发布者手动签发。

**更新时授权怎么处理**（`appversion/apply.go`）：

- 新版本的 `requires` **没有变宽**：除后台能力外的授权（含 Cloud 数据读写、数据权限）原样延续到新版本；
- `requires` **变宽**（新增能力或范围）：这些授权全部撤销，**不会自动重新授予**——重新打开应用后要在应用窗口「权限」（含底部「管理其他权限」）里重新勾选保存。打开窗口时宿主会主动弹出缺的授权：云数据授权缺项时弹「应用权限」，安装级权限缺项时弹「数据权限」（每个版本只主动弹一次，缺的项已预先勾好）；
- 后台能力逐项比较：权限没变宽的「延续」，变宽的「需要重新确认」，新版本删掉的「已移除」；
- 运行会话、文件票据一律作废，应用会重新加载。

### 在应用中心回滚

回滚入口在**更新确认框里**：「也可以回到上一个版本（x.y.z）。回滚同样会重建运行会话。」+ 按钮「**回滚到 x.y.z**」。

- 回滚目标固定为「最近一次升级之前的版本」，不能任选；
- 成功提示「{应用} 已回滚到 {版本}」，失败提示「回滚未完成，请稍后重试。」；
- 回滚只切换版本，**不回滚业务数据**。

> **升到最新后界面上找不到回滚**（注意）
>
> 回滚按钮只在「更新」确认框里出现。一旦你装的就是最新版本，这个应用不会出现在「更新」列表里，界面上就没有回滚入口——请用下面的 CLI `rollback`。

### 用 CLI 更新 / 回滚

```bash
zleap-app versions APP_ID      # 列出你可访问的版本及 version_id
zleap-app update   APP_ID --expected-version-id CURRENT_ID --version-id NEW_ID
zleap-app rollback APP_ID --expected-version-id CURRENT_ID --version-id OLD_ID
zleap-app uninstall APP_ID
```

CLI 走的是开发会话接口（`appinstallation/version.go` 的 `SwitchVersion`），规则比应用中心更严格：

- 必须给出**当前**和**目标** version_id；当前版本对不上（并发变化）就拒绝；`update` 只能切到更新的版本、`rollback` 只能切到更旧的版本；
- 目标版本仍要可见（本人上传或企业可见）、有效、Manifest 合法、运行能力可用；
- **如果新旧版本的 `data` 或 `storage` 声明有任何不同，返回 `DATA_MIGRATION_REQUIRED`（「数据结构变化需要显式迁移，未切换版本」），保持当前版本不变**。工具不会替你做数据迁移；
- 切换成功后：撤销所有旧会话和授权、**停用全部后台能力**，再按目标版本声明**重新授予**安装权限；数据绑定保留（回执 `data_preserved: true`）。

> **应用中心与 CLI 的差异**（提示）
>
> `DATA_MIGRATION_REQUIRED` 只在 CLI / MCP 的 `update`、`rollback` 中出现。应用中心的「更新」不做这项整体比较，而是按集合给出上表中的阻断 / 警告。

所有更新、回滚、卸载都**只影响你自己的个人安装**，不改目录当前版本，也不影响其他用户。

## 应用窗口顶部的按钮

打开一个上传的应用后，窗口内容区顶部有一条工具栏（靠右），从左到右：

| 按钮                             | 何时出现                                               | 作用                                        |
| -------------------------------- | ------------------------------------------------------ | ------------------------------------------- |
| **权限**                         | 应用声明了云能力或安装级权限时；两者都没声明时不显示   | 打开授权对话框，见下表                      |
| **已授权信息**                   | 你在授权框里同意过把头像昵称、手机号或邮箱给这个应用时 | 查看和撤销，见下文[已授权信息](#已授权信息) |
| **重新加载应用**（旋转箭头图标） | 所有上传的应用                                         | 重新取运行会话并重载 iframe                 |

「权限」按钮打开哪个对话框，取决于应用声明了什么：

| 应用声明                                                                                                                                                                       | 点「权限」                                                                                                       |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------- |
| 用了 Cloud：有 `runtime.backend`，或 `requires` 里有 `cloud.*` / `os.agent.complete`                                                                                           | 打开「应用权限」对话框（见下文）；若还声明了安装级权限，对话框底部有「**管理其他权限**」，进入「数据权限」对话框 |
| 只声明了安装级权限（`storage.kv` / `space.read` / `space.write` / `notify.send`，或 `host_api.requires` 里的 `clipboard.write` / `workspace.files` / `workspace.images.read`） | 直接打开「数据权限」对话框                                                                                       |

两类授权对应服务端两套独立闸门，**不要混为一谈**。

### 「应用权限」（Cloud 数据授权）

**标题**：应用权限

（截图：安装后打开应用，点窗口顶部「权限」打开的「应用权限」对话框，见文档站）

「应用权限」对话框：显示当前数据域、四项 Cloud 数据授权和「保存并重新加载」。

**说明**：

> 授权本应用读写它在应用云空间里的数据和文件。私有集合里的数据在应用里只对你本人展示；共享集合里的数据，本应用的其他使用者也能看到；应用的开发者可以在云开发控制台查看和管理这些数据。保存会关闭旧会话并重新打开应用。

下面一行显示**当前数据域**（由宿主决定，对话框里**没有**切换环境的选择器）：

| 数据域       | 文案                                                                         | 何时使用                                                                                 |
| ------------ | ---------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| dev（调试）  | 当前数据域：调试 —— 应用开发者调试用的数据，与正式使用的数据相互隔离。       | 部署**未开放**生产环境时所有人；应用成员装的是还没发布的开发版本，或应用还没有生产环境时 |
| prod（生产） | 当前数据域：正式 —— 本应用全体使用者的数据，共享集合按规则对其他使用者可见。 | 部署**已开放**生产环境时的其他使用者；应用成员装的版本已发布为线上版本时                 |

**四个复选框**：

| 复选框文案             | 对应能力               |
| ---------------------- | ---------------------- |
| **读取本人的应用数据** | `cloud.database.read`  |
| **修改本人的应用数据** | `cloud.database.write` |
| **读取应用文件**       | `cloud.storage.read`   |
| **上传和删除应用文件** | `cloud.storage.write`  |

勾选状态以服务端为准。因为安装时已授予声明的 Cloud 权限，正常安装后这几项**已经是勾选状态**；
勾选状态反映服务端实际授权；已撤销或尚未授予的项保持未勾选，需要使用者主动勾选并保存。Manifest 声明不会重新勾选已撤销的权限。只能授予 Manifest 声明过的能力，否则服务端拒绝「不能授予未声明能力」。

如果应用声明了后台能力，下方还有「**后台能力（定时任务 / 云函数）**」一组（当前数据域还没有环境时也会显示）：

> 授权后，本应用可在关窗后按你勾选的能力运行（如定时巡检），以你的身份读写你在本应用中的数据。

后台能力**已经启用**、但该版本还没有可用的签名发布时，会提示（刚勾上、还没保存时不提示：保存时平台会自动绑定版本已有的签名发布）：「该版本还没有可用的签名发布，暂时无法执行。重新保存一次权限会自动补签。」
正常不会看到这条提示：上传时平台已自动签名，保存权限或允许后台运行时会自动绑定（必要时当场补签）。

**主按钮**：**保存并重新加载**。二次确认：

> **确认修改应用权限？**
>
> 将修改此固定版本的应用数据和文件权限；服务端会重新校验授权。

保存后当前数据域的 Cloud 会话被撤销，应用重新加载。只要有**声明了却没授权**的项（数据项或后台能力），打开应用时会**自动弹出一次**这个对话框；
关掉后，窗口顶部按钮旁会常驻提示「还没授权：点「权限」勾选后保存，应用会自动重新加载。」

声明了安装级权限的应用，对话框底部还有一行「设置存储、空间文件、通知等其他权限」和「**管理其他权限**」按钮，点开即下文的「数据权限」对话框。

| 提示                                           | 含义                                                                            |
| ---------------------------------------------- | ------------------------------------------------------------------------------- |
| 当前安装未申请此能力，或你无权访问应用云空间。 | 读取授权失败。常见原因：在 dev 数据域下你不是应用成员——dev 默认只对应用成员开放 |
| 授权保存未确认，请重新读取后核对。             | 保存失败或结果不明，关掉重开对话框核对当前状态                                  |

> **生产未开放时，同事用不了 Cloud 数据**（注意）
>
> 部署未开放生产环境时，所有人都走 dev 数据域，而 dev 默认**只允许应用成员**访问（部署可另行放开）。
> 此时你把应用发布为线上版本后，同事能安装、能打开，但云数据读写会被拒绝。这属于「平台未开放」，不是你的代码写错了。

### 「数据权限」（安装级权限）

入口：「应用权限」对话框底部的「**管理其他权限**」；只声明了安装级权限、没用 Cloud 的应用，点窗口顶部「**权限**」直接打开。

当前版本声明了、但还没授权的安装级权限（例如新版本新加了 `storage`），打开应用窗口时会自动弹出这个对话框，并预先勾好缺的项；每个版本只主动弹一次，关掉后从入口自己改。没授权时应用调用会收到 40300，错误信息里写明缺哪项权限、去哪里开。

**标题**：`{应用名}` 的数据权限

**说明**：

> 默认不授予权限。以下权限只对"{应用名}"自己的应用数据生效，不会授权访问你其他应用或空间中的文件。勾选后点击保存才会授权。

> **说明文字与实际不完全一致**（提示）
>
> 这段说明写着「默认不授予权限」，但按安装即授权的规则，Manifest 里声明的这些能力**在安装时已经授予**，打开对话框会看到它们已勾选。这里主要用于**撤销**或重新勾选。

**复选框**（只列出该版本声明的项）：

| 复选框文案                               | 对应能力                |
| ---------------------------------------- | ----------------------- |
| **读取和保存此应用的设置**               | `storage.kv`            |
| **读取此应用中的个人文件**               | `space.read`            |
| **为此应用创建个人文件版本**             | `space.write`           |
| **发送此应用的通知**                     | `notify.send`           |
| **写入剪贴板**                           | `clipboard.write`       |
| **读取及整理你选定的空间文件夹内的文件** | `workspace.files`       |
| **读取你选定的空间文件夹内的图片**       | `workspace.images.read` |

后三项是 `host_api.requires` 里的宿主能力：安装时一并授予；**新版本才声明**的（切换版本不会自动授予），打开应用时同样自动弹出这个对话框让你补授权。

**按钮**：撤销全部 / 关闭 / 保存（未改动时不可点）

| 提示                                           | 含义                     |
| ---------------------------------------------- | ------------------------ |
| 此应用设置额度 {kv}，应用文件额度 {files}。    | 配额                     |
| 此版本未请求托管数据权限。                     | 该版本没声明这四项       |
| 数据权限已保存。 / 保存数据权限失败，请重试。  | 结果                     |
| 应用版本已更新。请重新加载权限列表后再次确认。 | 版本变了，点「重新加载」 |
| 当前账号无权修改此应用的权限。                 | 权限不足                 |
| 无法加载此应用的数据权限。                     | 读取失败                 |

### 工作文件夹（`workspace.files`）

声明了 `host_api.requires: ["workspace.files"]` 的应用，在调用时会弹出「选择工作文件夹 · {应用}」，其中写明：
「应用权限已在安装时授予。这里只选择工作范围；实际操作仍受你的空间权限限制。」——即这里**不是**再授权一次，只是选范围。
新版本才声明 `workspace.files` 时，授权在「数据权限」对话框里补（打开应用会自动弹出），之后再选文件夹。

### 已授权信息

应用调用 `zl.auth.authorize()` 申请你的信息时，会弹出系统授权框「**「{应用名}」申请获取你的以下信息**」，
列出申请的项目（头像和昵称、手机号、邮箱）和你自己的值，每一项都可以取消勾选，只给你愿意给的；应用写了用途时显示「用途：…」。
按钮「**拒绝**」/「**允许**」。没绑定手机号或邮箱时这一项置灰，显示「未绑定手机号」/「未绑定邮箱」。
授权框只会在你点击应用里的按钮之后出现，应用不能在打开时自动弹。

拒绝（或取消勾选）的项，**24 小时内**这个应用再申请也不会打扰你。

同意或拒绝之后，应用窗口顶部出现「**已授权信息**」按钮，打开后显示「你已允许这个应用获取：」和已授权的项目，以及 24 小时内拒绝过的项目。
点「**撤销授权**」（只有拒绝记录时是「**允许再次询问**」）即可收回并清除拒绝记录；应用下次申请时会重新弹出授权框。
同意过的信息不会重复询问，切换版本也不需要重新同意。

应用拿到的是本应用内的用户标识 `openid`，拿不到你的平台账号 ID 或登录令牌。开发者文档见 版本更新与授权登录（文档站 /reference/app-runtime#授权登录）。

## 应用加载异常

| 提示                                               | 原因                       | 处理         |
| -------------------------------------------------- | -------------------------- | ------------ |
| **正在准备应用…**                                  | 正在取运行会话或加载       | 等待         |
| **无法加载应用，请重试。**                         | 会话获取失败、安装已失效等 | 点「重试」   |
| **站点打开失败，请重试**                           | 空间站点票据获取失败       | 重试         |
| **文件打开失败，请检查应用或文件权限后重新打开。** | 用「打开方式」启动应用失败 | 检查文件权限 |

应用被管理员下架、被删除，或你的安装版本变化时，已打开的窗口会失效并显示「无法加载应用，请重试。」
