# 版本管理

控制台侧栏「发布」组下的这个入口，按应用类型显示为两个不同的页面：

| 应用                                                | 入口名称       | 做什么                                                                                        |
| --------------------------------------------------- | -------------- | --------------------------------------------------------------------------------------------- |
| 在控制台「创建应用」得到平台 `appid`（`zl…`）的应用 | **版本管理**   | 选一个开发版本「发布为线上版本」，全企业可见；回退、发布记录                                  |
| 旧的 `app_key` 命名空间应用                         | **版本与激活** | 发布候选、签名、激活开发 / 生产（见[版本与激活（旧 app_key 应用）](console-legacy-release.md)） |

> **应用中心「我的发布」与这里的关系**（提示）
>
> `appid` 应用的版本在应用中心显示「**仅成员可见**」（卡片统计为「企业 n / 开发版本 n」），成员版本上的主按钮是「**去版本管理发布**」，
> 点它会打开本页；已发布的版本显示「**企业可见**」，并保留「**云开发**」按钮。上线、回退都在本页完成。

## 版本管理

页头说明：

> 「成员每次上传都是一个开发版本。把其中一个「发布为线上版本」后全企业可见；回退就是把旧版本再发布一次。正在使用旧版本的人不会被打断，下次打开时自动更新。」

先认识两个名词：

| 名词         | 解释                                                                                                           |
| ------------ | -------------------------------------------------------------------------------------------------------------- |
| **开发版本** | 任何成员（管理员或开发者）每上传一次，就是一个开发版本。还没发布时只有成员能用                                 |
| **线上版本** | 当前对全企业生效的那一个版本。应用中心展示它、新安装装它、使用者自动跟随到它。一个应用同一时刻只有一个线上版本 |

### 页面内容

- 「**线上版本**」卡片：显示当前线上版本号和「全企业可见，新安装与自动更新都用这个版本」；
  还没发布过时显示「还没有发布过线上版本，只有成员能使用开发版本」。
- 「**发布说明（可选）**」输入框：最多 500 字，占位文字「这次更新了什么？会显示在发布记录里」。填写后对下一次发布生效。
- **版本列表**：列出所有成员上传的开发版本（新的在上），每行是版本号和「{上传者} 上传于 {时间}」（自己上传的显示「我」），以及标签：

  | 标签       | 含义                             |
  | ---------- | -------------------------------- |
  | **线上**   | 当前线上版本                     |
  | **曾发布** | 以前发布过、现在不是线上版本     |
  | **我在用** | 你本人的安装当前用的就是这个版本 |

- 「**发布记录**」：最近的发布，每条是「时间 · v版本号 · 发布说明」。

还没有任何上传时显示「还没有上传过版本」——「把 appid 写进 manifest 后运行 npm run deploy 上传第一个版本。」

（截图：版本管理页，见文档站）

版本管理页：上方是线上版本与发布说明，中间是版本列表和「发布为线上版本」；带云资源的应用下方还有「开发环境：云函数激活」。

### 每个版本的按钮

| 按钮               | 出现在                                     | 作用                                                                           |
| ------------------ | ------------------------------------------ | ------------------------------------------------------------------------------ |
| **发布为线上版本** | 比线上版本新的版本，或还没发布过线上版本时 | 把这个版本设为线上版本                                                         |
| **回退到此版本**   | 比线上版本旧的版本                         | 同样是「发布」，只是目标是旧版本                                               |
| **我也用这个**     | 你已安装该应用，且不是你正在用的版本       | 把**你本人**的安装切到这个版本，提示「已切换到 v{版本}，重新打开应用即可使用」 |

「我也用这个」对所有成员上传的开发版本都可点，包括同事刚上传、还没发布的版本——方便联调同事的改动。
不是成员的人看不到、也切不到开发版本。（个别在本次改版前上传的旧版本按钮置灰，悬停提示
「这个版本暂时不能直接使用（旧数据）；请上传者重新上传或发布为线上版本」。）

前提是你已经安装了这个应用：自己上传过版本（`npm run deploy` 会自动安装），或应用已发布、在应用中心装过。

发布和回退前都有确认框：

> **把 v{版本} 发布为线上版本？**
>
> 发布后全企业可见；正在使用旧版本的人不会被打断，下次打开时自动更新到这个版本。

> **回退到 v{版本}？**
>
> 线上版本改为 v{版本}。正在使用新版本的人下次打开时会回到这个版本。

成功后提示「已发布 v{版本} 为线上版本」/「已回退到 v{版本}」，失败提示「发布失败，请重试」或服务端给出的原因。

### 发布之后会发生什么

- **全企业可见**：没有单独的「上架」或可见性设置，发布即可见。应用出现在应用中心，新安装装的是线上版本。目前没有审核步骤。
- **谁都能发布**：管理员和开发者都可以发布、回退，不要求是这个版本的上传者。
- **正在用的人不被打断**：已经开着应用的人继续用原来的版本。应用可以用 `zl.app.getUpdateManager()` 提示用户立即更新，见 版本更新与授权登录（文档站 /reference/app-runtime）。
- **下次打开自动跟随**：不是应用成员的使用者打开应用时，如果线上版本和他装的不一样（发布了新版本，或回退了），
  宿主先把他切到线上版本，显示「**正在更新到最新版本…**」，再加载应用。
- **成员不自动切换**：管理员和开发者从不被自动切换，在本页用「我也用这个」自己选。
- **草稿应用不出现**：创建了但还没上传过任何版本的应用是草稿，不会出现在应用中心。

### 带云资源的版本

版本声明了 `data.collections`、任何 `cloud.*` 能力、`runtime.backend` 或 headless 的 `provides` 时，
「发布为线上版本」还会**以上传者的身份**准备好生产：开发与生产环境、生产数据域授权、签名、激活到生产、开通生产集合。
这些步骤由平台自动完成，**不需要你点「激活到生产」**（那个按钮只属于旧 `app_key` 应用），也不需要再手动做签名和激活。

这要求**上传者当前正在使用这个版本**，否则发布被拒绝：

| 业务码 | message                                          | `reason`                  | next_action                                                           |
| ------ | ------------------------------------------------ | ------------------------- | --------------------------------------------------------------------- |
| 40900  | 发布带云资源的版本前，上传者需要正在使用这个版本 | `UPLOADER_NOT_ON_VERSION` | 请上传者打开应用并切换到这个版本（npm run deploy 会自动切换），再发布 |

只用宿主能力、不需要任何云资源的版本，发布时不做这些准备。

**再次发布 / 回退到以前发布过的版本**：当时的生产准备已经做完，直接复用当时就绪的发布，不再要求上传者切回这个版本。

只有云函数、没有声明 `cloud.database.*` / `cloud.storage.*` 和集合的应用，准备时跳过「预授予数据权限」这一步。

### 带云资源的应用：开发环境云函数激活

带云函数 / 数据库的应用，「版本管理」页下方还有一块「**开发环境：云函数激活**」：只列出**你本人上传的**版本，
用于把它签名并激活到开发环境，云函数才能在开发环境运行（开发调试用；新建候选 → 签名验证 → 激活开发，步骤与旧应用相同，
见[版本与激活 · 激活开发](console-legacy-release.md#激活开发)）。也可以在项目里运行
`npx zleap-app prepare <app_id> --version-id <id>`，它只准备开发环境，不碰生产。给同事用不需要这里的操作，直接在上面「发布为线上版本」。

### 不需要云资源的应用：简化的控制台

应用当前版本不需要任何云资源时，控制台「概览」是一张简化页面：
「这个应用只用宿主能力，不需要开通数据库或云函数。上传的每个版本都在「版本管理」里，选一个发布为线上版本即可。」
下面有两个按钮：主按钮「**版本管理**」，第二个是成员入口——**管理员看到「去添加成员」，开发者看到「查看成员」**。
侧栏不显示「数据」「运行」两组，也没有环境切换。

### 用命令行发布

项目脚手架（`npm create zleap-app`）自带两条命令，用的是 `npm run login` 保存的开发会话：

```bash
npm run versions                                # 全部开发版本、当前线上版本、发布记录
npm run release -- --notes "修复预订冲突"        # 把最近一次 npm run deploy 的版本发布为线上版本
npm run release -- --version-id 6 --yes         # 发布 / 回退到指定版本（--yes 跳过确认，CI 里必须带）
```

发布会让全企业的使用者用上这个版本，所以交互终端里会先确认一次。直接用 CLI 时：

```bash
zleap-app releases <app_id>
zleap-app release <app_id> --version-id <version_id> [--notes 说明]
```

AI 开发工具（`zleap-app mcp serve`）里对应 `app_releases` / `app_release` 两个工具。只支持 `appid` 应用；
旧 `app_key` 应用调用返回 40900（`reason` 为 `LEGACY_APP`）。

### 接口

成员（管理员 / 开发者）可以调用：

| 接口                                                                                        | 说明                                                                                                                                                                 |
| ------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /api/v1/app-cloud/apps/{app_id}/versions`                                              | 全部开发版本、当前线上版本与最近的发布记录                                                                                                                           |
| `POST /api/v1/app-cloud/apps/{app_id}/publish`                                              | 请求体 `{version_id, notes?}`；返回 `{version_id, version, previous_version_id, published_at, notes, unchanged, prepared}`。回退就是用旧版本的 `version_id` 再调一次 |
| `GET /api/v1/app-dev/apps/{app_id}/releases` / `POST /api/v1/app-dev/apps/{app_id}/release` | 同上两条，用开发凭据（CLI）调用                                                                                                                                      |

`unchanged` 为 `true` 表示发布的就是当前线上版本；`prepared` 是带云资源的版本的生产准备结果，不需要准备时为 `null`。
`notes` 超过 500 字返回 42200「发布说明最多 500 字」。对旧 `app_key` 应用调用返回 40900「该应用使用旧的命名空间标识，请在「版本与激活」里管理版本」（`reason` 为 `LEGACY_APP`）。

使用者一侧的更新检查接口见 版本更新与授权登录 · 平台接口（文档站 /reference/app-runtime#平台接口-供参考）。
