# 上传与发布应用

这一篇讲左侧导航「**我的发布**」里与应用包有关的全部操作，以及与之等价的 `zleap-app` 命令行操作。

先分清两条上线路径——**用哪种应用，就走哪条路**：

| 应用类型                                                               | 上传后是什么                                                                    | 怎么让同事用上                                                                                          |
| ---------------------------------------------------------------------- | ------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| **平台 `appid` 应用**（在云开发控制台创建，形如 `zl3f9a2c7e1b0d4a68`） | **开发版本**，可见性 `members`：只有应用成员（管理员 / 开发者）能看到和安装     | 在云开发控制台「**发布 → 版本管理**」里点「**发布为线上版本**」；应用中心的「发布到企业目录」对它不适用 |
| **旧 `app_key` 应用**（形如 `com.example.my-app`）                     | 默认「仅自己可见」（`private`）；从应用中心上传时，如果已有企业可见版本则会继承 | 在应用中心点「**发布到企业目录**」；撤回也用应用中心                                                    |

```
appid 应用：
上传（应用中心 / CLI）──▶ 开发版本（members，仅应用成员可见）──▶ 控制台「版本管理」发布为线上版本 ──▶ 全企业可见

旧 app_key 应用：
上传 ──▶ 仅自己可见（private）──▶ 发布到企业目录（enterprise）──▶ 同事在「发现」安装
   │                                      │
   └─ 你自己可以直接安装调试               └─ 可随时「撤回企业目录」
```

> **几个容易混淆的「发布」**（提示）
>
>
> - **上传**：把 ZIP 变成一个固定版本。`appid` 应用得到的是「开发版本」，只有应用成员看得到、装得上；旧 `app_key` 应用默认只有你自己看得到。
> - **发布为线上版本**（仅 `appid` 应用，CLI 叫 `release`）：在云开发控制台「版本管理」里把**某一个开发版本**设为线上版本，全企业可见。**没有审核步骤**。
> - **发布到企业目录**（仅旧 `app_key` 应用，CLI 叫 `market-publish`、「上架」）：把**某一个版本**改成企业可见。**没有审核步骤**。
> - **签名与绑定**（让云函数 / 后台任务能跑）：`appid` 应用不需要手动操作——声明了后台能力的版本上传时平台自动签名，安装、切换版本时自动绑定；旧 `app_key` 应用在控制台「版本与激活」里手动新建发布候选、签名、激活。和目录可见性是两回事。
>

## 面板结构

「我的发布」顶部有一个三段切换：**自建应用** / **远程桌面** / **网页应用**。
你的应用包在「**自建应用**」下的「**应用包**」标签页里（同级还有「**自建站点**」标签页）。

「应用包」标签页里依次是：

- 标题「**应用包**」和统计「`N 个应用 · M 个版本`」；
- 提示「上传新版本，在应用卡片内管理目录可见性与云开发发布候选。」；
- 主按钮「**上传应用包**」和「**刷新**」；
- 应用卡片列表：**按应用分组**，同一个 `appid` 的多个版本收在一张卡片里。

（截图：「我的发布 → 自建应用 → 应用包」：应用卡片、目录状态与「管理版本」「⋯」按钮，见文档站）

「我的发布」按应用分组；卡片右侧的「管理版本」展开版本列表，「⋯」里是云开发控制台、编辑资料和删除。

没有上传过任何应用包时显示「你还没有发布应用包。」，并附一个「上传应用包」按钮。

## 上传应用包

> **平台 appid 应用：先在控制台创建应用**（提示）
>
> 使用平台 `appid` 时，上传前应用必须已在 [云开发控制台「创建应用」](console-members.md#创建应用)，并把生成的 `appid` 写进 `manifest.json`；
> 上传者必须是这个应用的成员（管理员或开发者）。旧 `app_key` 应用不需要这一步，按原有命名空间上传即可。

### 操作步骤

1. 点「**上传应用包**」。
2. 选择 `.zip` 文件。
3. 等待上传完成，成功提示：「**应用包已上传，可继续发布到企业目录。**」

`appid` 应用请忽略提示里的「发布到企业目录」——这只对旧 `app_key` 应用成立；`appid` 应用请去控制台「版本管理」发布线上版本，
也可以点版本行上的「**去版本管理发布**」直接打开。

前端预检不通过（不是 `.zip`、空文件、超过 20 MiB）时提示：

> 「请选择非空 ZIP 应用包，大小不超过 20 MiB。」

服务端校验失败时，界面统一提示：

> 「应用包上传失败，请检查 Manifest v2、权限和存储后重试。」

> **想看具体原因**（提示）
>
> 应用中心不展示服务端的具体错误。用 `zleap-app check ./my-app.zip --target <OS 地址>` 在本地或服务端做同一套校验，会给出原文（例如下表中的提示）。

### ZIP 结构要求（服务端校验）

以下限制来自 `zleap-service/internal/services/apparchive`：

| 要求                                                                                                        | 不满足时的服务端提示                                               |
| ----------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| ZIP 本身 ≤ 20 MiB、非空                                                                                     | 应用包必须是非空 ZIP，且不能超过 20 MiB                            |
| 根目录有 `manifest.json`，且 ≤ 1 MiB                                                                        | 应用包根目录必须包含 manifest.json / manifest.json 超过 1 MiB 上限 |
| JSON 合法、**不含重复键**                                                                                   | manifest.json 必须是有效 UTF-8 JSON，且不能包含重复键              |
| 根目录有**非空** `LICENSE`                                                                                  | 应用包根目录必须包含非空 LICENSE 文件                              |
| `appid` 是控制台生成的应用标识（旧应用为 `app_key` 命名空间，≤ 64 字符）                                    | manifest app_key 必须使用包含发布者前缀的小写命名空间              |
| `appid` 与 `app_key` 同时写时必须一致                                                                       | manifest 的 appid 与 app_key 不一致                                |
| `runtime.ui.type` 是 `iframe`                                                                               | 上传UI只支持iframe                                                 |
| `runtime.ui.entry` 指向包内存在的 `.html` / `.htm`                                                          | manifest entry 必须指向存在的包内 HTML 文件                        |
| 仅旧 `app_key` 应用：如写了 `publisher.publisher_id`，必须是你当前的用户 ID（`appid` 应用忽略 `publisher`） | 发布者声明不属于当前登录用户                                       |
| 条目数 1–2000                                                                                               | 应用包条目数量必须在 1 至 2000 之间                                |
| 单文件 ≤ 20 MiB；解压总大小 ≤ 80 MiB                                                                        | 应用包单文件大小超过上限 / 应用包解压总大小超过上限                |
| 单文件压缩比 ≤ 100                                                                                          | 应用包压缩比超过上限                                               |
| 不含符号链接、加密条目、`..` 等越界路径                                                                     | 应用包不允许符号链接或特殊文件 等                                  |

> **两个最常见的失败原因**（危险）
>
>
> **1. 多套了一层目录。** 解压后 `manifest.json` 必须直接在根：
>
> ```bash
> # ✅ 正确：进入目录内部再压缩
> cd my-app && zip -r ../my-app.zip .
>
> # ❌ 错误：把目录本身压进去了
> zip -r my-app.zip my-app/
> ```
>
> 更推荐直接用 `zleap-app pack ./my-app --output ./out/my-app.zip`：它生成确定性 ZIP，并自动排除 `.env*`、日志、私钥、依赖目录等。
>
> **2. 忘了 `LICENSE` 文件。** 内容非空即可。

### 版本号规则

| 情况                                    | 结果                                                                            |
| --------------------------------------- | ------------------------------------------------------------------------------- |
| `appid` 还没在控制台创建                | 拒绝：40400「appid 不存在」——先在云开发控制台「创建应用」                       |
| 你不是这个应用的成员                    | 拒绝：40300「你不是这个应用的开发者」——请管理员在控制台「成员」里把你加为开发者 |
| 旧 `app_key` 已被**其他人**的应用包占用 | 拒绝：「不能覆盖其他发布者的应用标识」（仅旧 `app_key` 应用）                   |
| 应用已被删除                            | 拒绝：「该应用已删除，不能使用原应用标识重新上传」                              |
| 同一版本号、**内容完全相同**的 ZIP      | 视为重复上传，直接返回已有的那个包                                              |
| 同一版本号、内容不同                    | 拒绝：「该版本已经存在，请更换版本号」——**改代码就要升版本号**                  |

### 上传后会自动发生什么

- 新版本的**可见性**由应用类型决定：
  - **平台 `appid` 应用**：无论从应用中心「上传应用包」还是用 CLI `zleap-app publish` 上传，得到都是**开发版本**，可见性固定为 `members`——只有应用成员能看到和安装。它**不会**继承企业可见，也**不会**自动变成线上版本。
  - **旧 `app_key` 应用**：应用中心「上传应用包」时，如果这个应用**已经有企业可见的版本**，新版本会**直接继承为企业可见**；否则为「仅自己可见」。CLI `zleap-app publish` **总是**「仅自己可见」，不继承（同版本号已公开时返回「该版本已公开，请使用新版本号上传private候选」）。
- 平台 `appid` 应用声明了后台（headless）能力的版本，平台在上传时**自动签名**，得到就绪发布，不需要再到控制台签名、激活。
- 旧 `app_key` 应用：如果部署配置了发布信任策略，会为这个版本自动建一个**发布候选（草稿）**，在控制台「版本与激活」里继续签名。详见 [版本与激活](console-legacy-release.md)。
- 上传**不会**替你安装，也**不会**授予任何权限。

> **旧 app_key 应用：从应用中心上传新版本，可能立即对同事可见**（注意）
>
> 如果你已经把旧版本发布到了企业目录，再从应用中心上传新版本时，它默认就是「企业可见」，同事可以在「更新」里升级到它。
> 想先自己验证再放出去，请用 `zleap-app publish`（固定 private），验证后再发布。

## 应用卡片

卡片头部：应用名、`appid`（旧应用为 `app_key`）、「最近上传 x.y.z · 大小 · 上传于 日期时间」。

右侧「**目录状态**」统计：`appid` 应用是「**企业 n**」「**开发版本 n**」，旧 `app_key` 应用是「**企业 N**」「**私有 N**」；
有停用版本时再加「**停用 N**」，以及「**N 个版本**」。

右侧按钮：

- 「**管理版本**」展开版本列表（展开后变成「**收起版本**」）；
- 「⋯」菜单：「**云开发控制台**」「**编辑应用资料**」「**删除应用**」。

### 版本列表

展开后标题「**版本列表**」，说明：「目录上下架作用于单个版本；云开发负责运行环境、发布候选与生产门禁。」
`appid` 应用的说明是：「这是 appid 应用：每次上传都是只有应用成员可见的开发版本，在云开发控制台「版本管理」里发布为线上版本后全企业可见。」

每一行：

| 位置 | 内容                                                                                                                                 |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------ |
| 左   | 版本号；最新上传的那一行带「**最近上传**」标记                                                                                       |
| 中   | 上传时间、包大小                                                                                                                     |
| 状态 | 「**仅自己可见**」「**仅成员可见**」或「**企业可见**」；已停用的版本另有「**已停用**」                                               |
| 按钮 | 「**云开发**」→ 打开控制台的版本页并定位到这个版本（旧应用，以及 `appid` 应用已发布的版本）                                          |
| 按钮 | 「**发布到企业目录**」（旧应用当前私有）或「**撤回企业目录**」（旧应用当前企业可见）；`appid` 应用的成员版本是「**去版本管理发布**」 |

已停用的版本没有发布 / 撤回 / 去版本管理发布按钮，「云开发」按钮也不可点。

> **平台 appid 应用在「我的发布」里看到什么**（提示）
>
> `members` 版本显示「**仅成员可见**」，卡片统计为「**企业 n / 开发版本 n**」。版本列表上方会有提示：
> 「这是 appid 应用：每次上传都是只有应用成员可见的开发版本，在云开发控制台「版本管理」里发布为线上版本后全企业可见。」
> 成员版本没有「发布到企业目录」，只有「**去版本管理发布**」（打开控制台「版本管理」）；
> 发布为线上版本后，版本可见性变为 **enterprise（企业可见）**，显示「**企业可见**」并保留「**云开发**」按钮。

## appid 应用：发布为线上版本

平台 `appid` 应用的上线**只在云开发控制台里完成**，不走应用中心的「发布到企业目录」。

1. 打开云开发控制台（系统内置应用，启动台「更多工具」里，或搜索「云开发」直接打开），在顶部应用切换器选中你的应用。
2. 侧栏点「**发布 → 版本管理**」。
3. 页面上方是「**线上版本**」：没发布过时显示「还没有发布过线上版本，只有成员能使用开发版本」。
4. 在下方版本列表里找到要上线的开发版本（每个版本都标出上传者和上传时间），点「**发布为线上版本**」。可以填写「发布说明（可选）」。
5. 确认「把 v{版本} 发布为线上版本？」。

（截图：云开发控制台「版本管理」：线上版本、发布说明、版本列表与「发布为线上版本」，见文档站）

「版本管理」上方是线上版本和发布说明，下方列出全部成员上传的开发版本，每个版本都可以「切换到此版本」（只切你自己桌面上的应用）、「发布为线上版本」或「回退到此版本」。
**任一成员都可以发布任一版本**，包括同事上传的版本。

发布后**全企业可见**：新安装装的就是它，不是应用成员的使用者下次打开应用时自动更新。**回退**就是把一个旧版本再「发布为线上版本」，按钮文案是「回退到此版本」。

> **带云资源的版本第一次发布**（注意）
>
> 带数据库集合、`cloud.*` 能力或云函数的版本**第一次**发布时，平台自动完成**应用级**生产准备：生产环境 → 签发生产发布（归属上传者）→
> 生产门禁（签名、审批窗口、信任策略核对）→ 生产库与生产集合。不依赖任何人的安装。可能返回 40900（看 `detail.reason`）：
>
> - `PROD_DATABASE_NOT_READY`「生产数据库还没就绪，暂时不能发布」：通常 1 分钟内就绪，稍后在版本管理里重新发布；持续失败请在控制台「数据库」查看状态。
> - `UPLOADER_INACTIVE`「这个版本的上传者账号已停用，无法发布」：请其他成员重新上传这个版本（`npm run deploy`）后再发布。
> - 生产门禁不通过（如 `RELEASE_APPROVAL_EXPIRED_OR_MISSING`、`RELEASE_POLICY_STALE`、`PRODUCTION_RELEASE_UNAVAILABLE`）：重新发布即会重新签发。
>
> 已经发布过的版本再次发布（包括回退）直接复用当时的就绪发布。只用宿主能力、没有云资源的应用发布即可用，不需要签名。

### CLI 等价操作（appid 应用）

```bash
zleap-app releases APP_ID                         # 列出全部成员上传的开发版本、当前线上版本和发布记录
zleap-app release APP_ID --version-id VERSION_ID --notes "这次更新了什么"
```

- `release` 必须用 `--version-id` 明确指定版本，不会自动挑最新；
- 回退同样用 `release` 指向一个旧版本；
- 脚手架项目里是 `npm run versions` / `npm run release`；
- 上传（`zleap-app publish`）只生成开发版本，发布线上版本要再执行 `release`。

## 发布到企业目录（仅旧 app_key 应用）

> **appid 应用不适用**（注意）
>
> 这一节只适用于旧 `app_key` 应用。平台 `appid` 应用调用「发布到企业目录」（或 CLI `market-publish`）会被服务端拒绝：
> 409 `USE_VERSION_MANAGEMENT`「这个应用请在云开发控制台「版本管理」里发布或回退」。请用上一节的「发布为线上版本」。

点某个版本行的「**发布到企业目录**」，确认框：

> **发布"应用名 版本号"到企业目录？**
>
> 企业用户将能在应用中心看到这个固定版本。发布不会授予 Agent 或生产后台权限。

确认后提示「**应用包已发布到企业目录。**」；失败提示「发布范围更新失败，请刷新后重试。」

服务端会做的事：

1. 只有**版本的上传者**（或平台管理员）能改可见性；
2. 发布前**重新校验**这个版本的 Manifest；
3. 把这个应用在目录里的「当前版本」更新为**最新的企业可见版本**——别人在「发现」里看到、点「安装」装上的就是它。

> **「固定版本」是什么意思**（提示）
>
> 发布的是**这一个版本**，不是整个应用。别人安装后，他们的安装就固定在这个版本，直到他们自己在「更新」里升级。
> 你之后发布更新的版本，已安装的同事会在「更新」里看到「已安装 旧 → 最新 新」。

### CLI 等价操作（旧 app_key 应用）

```bash
zleap-app publish ./out/my-app.zip --target https://os.example.com
# 回执顶层有 app_id / version_id / package_id
zleap-app market-publish <package_id> --app-key zl3f9a2c7e1b0d4a68     # 设为企业可见（--app-key 填 appid）
zleap-app market-unpublish <package_id> --app-key zl3f9a2c7e1b0d4a68   # 撤回为仅自己可见
```

- `market-publish` 只适用于**旧 `app_key` 应用**；`appid` 应用请用 `zleap-app release`（见上一节）；
- `market-publish` 的参数是 **package_id**（固定版本），不是 app_id；
- 只能操作**本人**、**当前登录限域的 appid** 下的应用包；与应用中心按钮走同一个可见性服务，同样没有审核；
- 需要带 `package.own.market` 权限的开发会话；旧会话请重新 `zleap-app auth login`；
- 网络超时返回 unknown 时，先 `zleap-app status` 查该 package_id 的实际 visibility，不要盲目重试。

## 撤回企业目录（仅旧 app_key 应用）

`appid` 应用没有「撤回企业目录」这一步：让线上版本回到旧版本，是在控制台「版本管理」里对旧版本点「回退到此版本」。下面只适用于旧 `app_key` 应用。

点「**撤回企业目录**」，确认框：

> **从企业目录撤回"应用名 版本号"？**
>
> 撤回后新用户将无法发现此版本；其他人已安装的这个版本将无法再打开（你自己的安装不受影响）。安装记录和应用数据不会被删除，重新发布到企业目录后可恢复使用。

确认后提示「**应用包已从企业目录撤回。**」

> **撤回会让同事的已有安装打不开**（危险）
>
> 服务端在打开应用时会检查：**不是上传者本人、且该版本不再企业可见** → 拒绝运行（「应用运行授权已失效」/「应用包版本不存在或无权访问」）。
> 装着这个版本的其他用户**会立刻无法打开应用**，直到你重新发布这个版本，或他们升级到另一个企业可见版本。

## 编辑应用资料

「⋯」→「**编辑应用资料**」打开「**应用资料**」抽屉：「完善应用介绍和预览，让大家更容易了解你的应用。资料修改不需要重新上传应用包。」

| 字段             | 限制                                                         |
| ---------------- | ------------------------------------------------------------ |
| 应用名称         | 必填                                                         |
| 应用介绍         | 显示在详情页「介绍」                                         |
| 开发者、应用官网 | 官网需完整 `http://` / `https://` 地址                       |
| 应用图标         | PNG、JPEG 或 WebP，最大 5 MiB                                |
| 宣传图与应用预览 | 最多 8 张 PNG、JPEG 或 WebP，每张最大 10 MiB，按上传顺序展示 |

点「**保存资料**」后提示「应用资料已保存。」部分失败时提示「应用资料未全部保存」，已保存的部分会保留。
发布者在自己应用的详情页「介绍」里也能看到同一个「编辑应用资料」按钮。

## 删除应用

> **删除是整应用级的破坏性操作**（危险）
>
> 「⋯」→「**删除应用**」，确认框：
>
> > **删除"应用名"？**
> >
> > 将删除该应用的 N 个发布版本并撤销企业目录、安装、运行会话、Cloud 授权和发布候选。企业可见版本：N。已打开的沙箱会被宿主卸载，运行中的 Cloud sandbox 会失去授权并由 worker/reaper 回收。用户数据、Cloud 数据和归档文件会保留在清理保留期内，不会在此操作中直接清空。
>
> 成功提示二选一：「应用已删除，运行权限已撤销。」或「应用已删除，运行权限已撤销；归档和 Cloud 资源已标记待清理。」
>
> 删除影响**所有用户**的安装。删除后这个 `appid`（或旧 `app_key`）**不能再上传**（「该应用已删除，不能使用原应用标识重新上传」）。
> 只想让新用户看不到，请用「撤回企业目录」。

## 管理员下架

平台管理员可以在「应用管控」里把整个应用**下架**：对所有非管理员隐藏，已安装用户也看不到。
下架与你的发布互相独立——你重新发布到企业目录（旧应用）或重新发布线上版本（`appid` 应用）**不会**解除管理员下架。

## 操作结果不确定时

安装 / 卸载这类操作在网络中断后，界面可能显示：

> **尚未确认操作结果**
>
> 请先重新读取安装状态。不要重复提交；当前服务尚未提供可恢复的操作记录。

并提供「**检查结果**」按钮。被明确拒绝时显示：

> **操作已被拒绝**
>
> 此次请求未成功。请检查权限与应用状态后重新操作；已有安装记录不能证明本次请求成功。

平台**不会**把「读到了某个已有状态」当作「你刚才那次操作成功了」。
