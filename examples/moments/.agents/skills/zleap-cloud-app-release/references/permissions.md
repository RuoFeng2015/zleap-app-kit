# 权限与授权

这一篇解释：应用的权限从哪来、在哪里能改、和「数据能不能读到」之间还隔着哪些条件，以及各种「没权限」报错怎么排查。

> **一句话版本**（提示）
>
> **声明即申请，安装即授权。** 安装时，平台把这个固定版本在 Manifest 里声明的权限一次性授予给安装者；
> 但**后台能力（定时任务 / 云函数）默认停用**，必须由用户显式启用。授权之外，云资源还要就绪、数据面 ACL 还要通过，调用才会成功。

## 权限要过的几道关

```
① Manifest 声明         应用说「我需要读数据库」（runtime.capabilities.requires 等）
        ↓  安装
② 安装授权（自动）      安装时授予声明的权限；后台能力预置为「停用」
        ↓  用户可在应用窗口里调整
③ 运行时开关            应用窗口「权限」里的勾选；后台能力需显式启用
        ↓
④ 资源与 ACL            环境 / 数据库 / 集合已就绪；数据域对你开放；集合规则通过
        ↓
⑤ Provider 收窄         云函数 / 内置动作只能碰它声明的集合、动作和字段
```

任一关不过，调用就失败。Manifest 写对了不代表能读到数据；有权限也不代表函数能碰所有字段。

## 第一关：Manifest 声明

在 `runtime.capabilities.requires` 里声明云能力：

```json
{
  "id": "cloud.database.read",
  "reason": "读取我的待办事项",
  "scope": "current_user",
  "optional": false
}
```

| 字段       | 作用                                         |
| ---------- | -------------------------------------------- |
| `id`       | 能力标识                                     |
| `reason`   | 写清楚为什么需要（给使用者看的理由）         |
| `scope`    | 数据范围，通常是 `current_user`              |
| `optional` | 是否可选；可选能力不在白名单里也不会阻断安装 |

### 目前开放的能力（`requires` 白名单）

| 能力 ID                | 含义                                           | 备注                             |
| ---------------------- | ---------------------------------------------- | -------------------------------- |
| `cloud.database.read`  | 读取本应用数据库                               |                                  |
| `cloud.database.write` | 写入本应用数据库                               |                                  |
| `cloud.storage.read`   | 读取本应用存储文件                             |                                  |
| `cloud.storage.write`  | 写入本应用存储文件                             |                                  |
| `os.agent.complete`    | 调用系统 Agent                                 | 必须同时声明 `runtime.backend`   |
| `os.work.read`         | 读取本人工作数据（待办、项目任务、文档元数据） | 配合 `builtin` 动作 `os.work.*`  |
| `os.todos.read`        | 读取本人系统待办                               | 配合 `builtin` 动作 `os.todos.*` |
| `os.todos.write`       | 写入本人系统待办                               | 需同时声明 `os.todos.read`       |

> **声明白名单之外的非可选能力**（危险）
>
> 应用会被判为**不可运行**（`FEATURE_UNAVAILABLE`），在应用中心显示「暂不可用」，**无法安装**。
> 确实想声明但暂不可用的能力，设 `optional: true`。

除 `requires` 外，以下声明也属于安装时要授予的权限：

| 声明位置                                                     | 可用值                                                                           | 在哪里调整                                                                   |
| ------------------------------------------------------------ | -------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| `host_api.requires`                                          | `clipboard.write`、`workspace.files`、`workspace.images.read`、`credentials.use` | 不可在窗口里单独撤销                                                         |
| `host_api.requires`（个人信息）                              | `user.profile`、`user.phone`、`user.email`                                       | 安装时**不授予**，使用时由用户在授权框里逐项同意；应用窗口「已授权信息」撤销 |
| 顶层 `capabilities` / `storage.capabilities`（宿主托管数据） | `storage.kv`、`space.read`、`space.write`、`notify.send`                         | 应用窗口「权限」                                                             |

### 也要声明集合

数据库能力只管「能不能读写」，具体能碰哪些集合由 `data.collections` 决定，**没声明的集合访问会失败**：

```json
"data": {
  "collections": ["todos", "board"],
  "default_binding": "current_user",
  "shared_collections": ["board"]
}
```

集合在数据库开通后**按声明自动创建**，控制台不能单独新建集合。详见 Manifest · data（文档站 ./manifest）。

## 第二关：安装即授权

点「安装」并确认（或 CLI `zleap-app install`）时，服务端在**同一个事务**里把该版本声明的权限授予给你：

- `cloud.database.*` / `cloud.storage.*` 同时授予 **dev 和 prod** 两个数据域；
- `os.*`、`host_api.requires`、宿主托管数据能力按声明原样授予；
- 授权绑定「你 × 这个安装 × 这个版本」；写入失败则整个安装回滚。

安装确认框会逐行列出这些权限，文案见 [安装与卸载](app-center-install.md)。

**不会**在安装时发生的事：

| 不会自动发生          | 需要什么                                                                                     |
| --------------------- | -------------------------------------------------------------------------------------------- |
| 后台能力运行          | 安装时预置为「停用」，必须显式启用（见下文「后台能力的授权」）                               |
| 云数据库 / 存储能读写 | 当前数据域有环境且数据库就绪（声明了集合的应用安装时自动创建开发环境），且你能访问当前数据域 |
| Agent 调用你的应用    | 安装不授予 Agent 调用权限                                                                    |

卸载会撤销该安装的全部授权和后台能力激活，**应用数据保留**；重新安装会重新授予声明的权限，后台能力仍需重新启用。

## 第三关：应用窗口里的「权限」按钮

打开应用后，窗口内容区顶部右侧只有**一个**「**权限**」按钮，但背后是两类**独立**的授权，对应服务端两套闸门，不要混为一谈：

| 授权                                     | 管什么                                                      | 怎么打开                                                                                                |
| ---------------------------------------- | ----------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| **Cloud 数据授权**（「应用权限」对话框） | 云数据库 / 存储读写、后台能力                               | 应用声明了 `runtime.backend`，或 `requires` 里有 `cloud.*` / `os.agent.complete` 时，点「权限」直接打开 |
| **安装级权限**（宿主托管数据）           | `storage.kv` / `space.read` / `space.write` / `notify.send` | 在「应用权限」对话框底部点「**管理其他权限**」；只声明了这些权限、没用 Cloud 的应用，点「权限」直接打开 |

两类都没声明的应用不显示「权限」按钮。两个对话框的完整文案见 [安装与卸载 · 应用窗口顶部的按钮](app-center-install.md)。这里只讲授权语义。

### 「Cloud 数据授权」（「应用权限」对话框）

四个复选框：

| 复选框             | 对应能力               |
| ------------------ | ---------------------- |
| 读取本人的应用数据 | `cloud.database.read`  |
| 修改本人的应用数据 | `cloud.database.write` |
| 读取应用文件       | `cloud.storage.read`   |
| 上传和删除应用文件 | `cloud.storage.write`  |

如果应用声明了后台能力，下面还有「**后台能力（定时任务 / 云函数）**」一组，每项一个复选框（当前数据域还没有环境时也会显示）。

- 勾选状态以服务端为准。因为安装即授权，正常安装后四项**已经是勾选状态**；声明了但未授权的项会被预勾选（只是默认值，点保存才生效）；
- 只能授予 Manifest 声明过的能力，否则服务端拒绝「不能授予未声明能力」；
- 点「**保存并重新加载**」并确认「确认修改应用权限？」后，服务端**撤销该数据域的旧 Cloud 会话**，应用重新加载；
- 有声明了却没授权的项（数据项或后台能力）时，打开应用会自动弹出一次这个对话框；关掉后按钮旁常驻提示「还没授权：点「权限」勾选后保存，应用会自动重新加载。」

### 数据域由宿主决定

对话框里**没有环境选择**。数据域（dev「调试」/ prod「生产」）由宿主根据部署决定，对话框只显示当前是哪个：

| 部署状态   | 数据域 | 谁能用                                                                                                                              |
| ---------- | ------ | ----------------------------------------------------------------------------------------------------------------------------------- |
| 未开放生产 | dev    | 默认只有开发团队：这个应用的全部成员（其他人报 `PUBLISHER_REQUIRED`，对话框显示「当前安装未申请此能力，或你无权访问应用云空间。」） |
| 已开放生产 | prod   | 其他安装者一律走生产（应用没有生产环境时报 `ENV_FORBIDDEN`）；发布者本人在应用有生产环境后走生产，否则仍走 dev                      |

生产是否开放取决于部署：发布信任配置就绪即开放（由运维自动配置），不由应用决定。
应用代码里只写 `zl.cloud.init({ env: zl.cloud.DYNAMIC_CURRENT_ENV })`，**不要写死 `'dev'` / `'prod'`**。

> **生产未开放时，同事用不了 Cloud 数据**（注意）
>
> 此时所有人都走 dev，而 dev 默认只对开发团队（这个应用的全部成员）开放（部署可另行放开）。你把应用发布为线上版本后，
> 同事能安装、能打开，但云数据读写会被拒绝。这属于「平台未开放」，不是代码写错了。

### 授权与会话的关系

应用打开时，宿主为当前数据域建立 Cloud 会话，并按此刻的授权**一次性算出**可用的能力集合（profiles）：

| profile            | 需要                                                 | 缺了的现象                                                                                                         |
| ------------------ | ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `document-core/1`  | 数据库已开通 + 声明了集合 + 至少授权了数据库读或写   | 数据库调用抛 `UNSUPPORTED_OPERATION`                                                                               |
| `watch-snapshot/1` | 上面 + 授权了数据库读                                | `watch` 不可用                                                                                                     |
| `storage-object/1` | 存储已启用 + 授权了文件读/写（生产还需绑定就绪发布） | 文件接口抛 `UNSUPPORTED_OPERATION`                                                                                 |
| `app-execution/1`  | 至少一项后台能力已启用                               | `callFunction` / `capabilities.invoke` 抛 `BACKGROUND_CAPABILITY_UNAVAILABLE`（旧 SDK 抛 `UNSUPPORTED_OPERATION`） |

数据库和存储一项都没授权、也没有已启用的后台能力时，会话直接被拒：`CONSENT_REQUIRED`。

**改了授权一定要重新加载应用**——旧会话的 profiles 不会自己变。

### 授权绑定在「安装 × 环境 × 版本」上

Cloud 授权的键形如 `cloud.database.dev.read`，记录在**这个安装的这个版本**上：dev 与 prod 分开记录，换版本就是另一组记录。
切换版本时授权怎么处理，取决于你用的入口（详见 [安装与卸载 · 更新与回滚](app-center-install.md)）：

| 入口                            | 授权                                                                            | 后台能力                                                                   |
| ------------------------------- | ------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| 应用中心「更新」/「回滚」       | `requires` 没有变宽：原样延续到新版本；变宽：相关授权撤销，需要在窗口里重新勾选 | 逐项比较：没变宽的「延续」，变宽的「需要重新确认」，新版本删掉的「已移除」 |
| CLI / MCP `update` / `rollback` | 撤销旧授权，按目标版本声明**重新授予**                                          | **全部停用**，需重新启用                                                   |

无论哪个入口，切换后运行会话都会作废，应用重新加载。

> **为什么绑定到版本**（提示）
>
> 用户授权的是**这个固定版本**的代码。权限变宽的新版本不会悄悄继承旧授权。

## 后台能力的授权

「关掉窗口后还能跑」需要**单独**的授权，安装时一律是停用。两个地方都能启用，作用相同：

| 位置                                                            | 操作                                       |
| --------------------------------------------------------------- | ------------------------------------------ |
| 应用窗口「权限」→「后台能力（定时任务 / 云函数）」              | 勾选后「保存并重新加载」                   |
| [云开发控制台 → 云函数 → 后台能力](console-functions.md#后台能力) | 「允许后台运行」/「撤销授权」/「重新授权」 |

对话框里的说明：

> 授权后，本应用可在关窗后按你勾选的能力运行（如定时巡检），只作用于你本人的数据，其他使用者看不到。

- 授权限定在**这个安装 + 这个版本 + 这个环境**；每一步执行前都会重新检查；
- `managed_function`（云函数）还要求绑定**就绪**的签名发布，否则该项下方提示「该版本还没有可用的签名发布，暂时无法执行。重新保存一次权限会自动补签。」，调用返回 `FUNCTION_RELEASE_REQUIRED`。带后台能力的版本上传时由平台自动签名；在这里保存（或允许 / 撤销后台运行）时自动绑定，缺签时当场补签，正常不会看到这条提示；
- `logic_unit` / `builtin` provider 不需要发布；
- `os.agent.complete` 等内置动作同样是一项后台能力，要在这里启用后才能调用。

| 操作                        | 效果                                                               |
| --------------------------- | ------------------------------------------------------------------ |
| 启用（勾选 / 允许后台运行） | 该能力可被应用、控制台试运行和触发器调用                           |
| 撤销                        | 不能再调用，触发器停止，阻止**新步骤**；**已经写入的修改不会回滚** |

> **「关窗不取消后台授权」+「已提交不回滚」**（危险）
>
> 用户关掉窗口后，已启用的定时任务**会继续跑、继续写数据**。不想让它继续跑，必须明确撤销；
> 撤销只阻止后续步骤，已经写进去的数据要自己核对处理。

## 第五关：Provider 权限

每个 backend provider 可以在 Manifest 里**再收窄一次**自己能访问的范围：

```json
{
  "id": "ticket.classify",
  "type": "managed_function",
  "function": "classifyTicket",
  "permissions": {
    "capabilities": ["cloud.database.read", "cloud.database.write"],
    "data": [
      {
        "collection": "tickets",
        "scope": "current_user",
        "actions": ["get", "update"],
        "fields": ["subject", "priority", "tags"]
      }
    ]
  }
}
```

| 字段           | 含义                                                  |
| -------------- | ----------------------------------------------------- |
| `capabilities` | 该 provider 可用的能力，**必须 ⊆ `requires`**         |
| `collection`   | 只能碰 `tickets` 集合（必须在 `data.collections` 里） |
| `scope`        | 只能碰当前用户的数据                                  |
| `actions`      | 只能读单条和更新：**不能新建、不能查询、不能删除**    |
| `fields`       | 只能碰这三个字段                                      |

前两条（子集、集合已声明）不满足时，**上传即被拒绝**。

> **云函数的 `fields` 不能省略**（注意）
>
> Manifest 校验技术上允许省略 `fields`（默认空数组），但云函数的数据网关把空 `fields` 当成「没有任何字段授权」，读写都会被拒（「云函数数据字段未授权」）。
> 网关逐请求核对的完整规则见 云函数开发（文档站 ./cloud-function）。

`actions` 合法值：`get`、`query`、`count`、`add`、`set`、`update`、`remove`。注意 `get` 是按文档键读**单条**，`query` 是按条件**查多条**——
只给 `get` 不给 `query`，函数就不能批量扫描。

`scope` 合法值：`invocation`、`current_user`（最常用）、`user`、`space`、`organization`。

## 私有数据 vs 共享数据

每个集合有一个**分区**（partition），决定数据归谁：

| 类型                    | 控制台显示 | 声明方式                                                                          | 行为                           |
| ----------------------- | ---------- | --------------------------------------------------------------------------------- | ------------------------------ |
| 私有（`private`，默认） | 使用者隔离 | 只列在 `data.collections`                                                         | 每个用户只看得到自己的文档     |
| 共享（`shared`）        | 环境共享   | 列入 `data.shared_collections`，**或** `data.policies.<集合>.partition: "shared"` | 同一环境内所有用户共用一份数据 |

```json
"data": {
  "collections": ["todos", "board"],
  "shared_collections": ["board"],
  "policies": {
    "board": { "partition": "shared", "read": "doc.visible == true" }
  }
}
```

- `shared_collections` 必须是 `collections` 的子集；
- 同一集合既列在 `shared_collections` 又写了 `policies` 时，必须显式写 `partition: "shared"`，否则冲突被拒；
- 分区在集合**创建时**确定，之后的版本不能改（应用中心更新预检报 `COLLECTION_PARTITION_IMMUTABLE`）；
- `partition: "app"` 目前未开放。

记录规则（`read` / `write`）的写法见 Manifest · data（文档站 ./manifest）。

> **共享集合里不要放隐私数据**（危险）
>
> 共享 = 环境内所有用户可见。工单内容、审计日志这类可能含个人信息的集合，列入共享前要确认业务上确实需要全员可见。

## Agent 与应用的调用关系

| 方向                          | 怎么做                                                                       | 约束                                                                                                |
| ----------------------------- | ---------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| 应用 → 系统 Agent             | 声明 `builtin` provider（`action: "os.agent.complete"`）+ headless 能力      | 需声明 `os.agent.complete` 和 `runtime.backend`；需启用这项后台能力；只返回**提案文本**，不自动写库 |
| 应用 → 本应用数据（平台动作） | `builtin` provider 绑定 `clouddb.document.get` / `clouddb.document.update`   | 需要 `cloud.database.read` / `write`，按 provider `permissions.data` 收窄                           |
| 宿主 / 控制台 → 应用能力      | 用已启用的后台能力调用应用公开的 headless 能力（如控制台「试运行」、触发器） | 需要该能力已启用                                                                                    |

> **普通 SDK 不能跨应用调用**（危险）
>
> iframe 里的应用**不能**自己指定其他应用的 `app_id` 去调用对方的能力。跨应用调用只能由宿主或云开发控制台以受控方式发起；
> 本文档站未验证跨应用委托的具体流程。

### `agent.interaction` 为什么不能用

`manifest.json` 里有一个 `agent.interaction` 字段（让 Agent 驱动**前台界面**）。**当前不要声明它**：
声明即被判为不可运行（应用中心「暂不可用」），前台 provider 的执行通道也尚未开放。
需要「Agent 读写应用数据」时，用上表的 headless 能力 + 平台动作实现。

## `host_api` 宿主能力

宿主能力由桌面外壳提供，**不走 Cloud SDK**：

```json
"host_api": {
  "profile": "app-runtime/2",
  "requires": ["clipboard.write"]
}
```

| 能力                    | 说明                             | 用法                                                                                                                                      |
| ----------------------- | -------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `clipboard.write`       | 写入剪贴板                       | 宿主桥支持这个能力，但当前 SDK 的 `connectHostedApp()` 只有 `kv`、`files`、`close`，**没有剪贴板方法**；本文档站暂不提供调用示例          |
| `workspace.files`       | 读取及整理选定空间文件夹内的文件 | 模板里的 `sdk/workspace.js`；运行时由用户选择工作文件夹                                                                                   |
| `workspace.images.read` | 读取选定文件夹里的图片           | 需同时声明 `workspace.files`；`workspace.readImage(handle, fileId, expectedVersion)` 返回校验过的图片 Blob（JPEG/PNG/GIF/WebP，≤ 20 MiB） |
| `credentials.use`       | 使用钥匙串里的登录凭据           | 宿主桥能力；当前 SDK 未提供封装，本文档站暂不展开                                                                                         |

- `host_api.profile` 必须是 `app-runtime/2`；`requires` 写了白名单之外的值，应用变成不可运行；
- 宿主桥会拒绝**未声明**的方法调用，返回错误而不是静默忽略；
- `workspace.files` 弹出的「选择工作文件夹」只是选范围，权限已在安装时授予，实际操作仍受你的空间权限限制；
- `workspace.files` 与 `cloud.storage.*` 是两回事：后者是本应用自己的云存储，不能互相代替；
- 没用到的能力不要写——声明的每一项都会出现在安装确认框里。

## 排查「没权限」

| 症状                                                 | 检查项                                                                                                                                                        |
| ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 应用显示「暂不可用」，装不上                         | `requires` 里有白名单外的非可选能力？声明了 `agent.interaction`、前台 provider / 前台 provides？`host_api` 写错？                                             |
| 上传就失败                                           | `appid` 是否已在控制台创建、你是否是应用成员、provider `permissions` 是否 ⊆ `requires`、集合是否已声明                                                        |
| 打开应用报 `CONSENT_REQUIRED`                        | 「权限」里的四项全被取消且没有已启用的后台能力——勾选后保存                                                                                                    |
| `PUBLISHER_REQUIRED`                                 | 当前数据域是 dev，而你不是该版本的发布者。等部署开放生产，或用发布者账号验证                                                                                  |
| `ENV_FORBIDDEN`                                      | 当前数据域的环境未创建 / 不可用，或部署未开放生产                                                                                                             |
| 数据库调用 `UNSUPPORTED_OPERATION`                   | 环境、数据库是否就绪？是否授权了数据库读写？改完后重新加载应用了吗？                                                                                          |
| `SCOPE_FORBIDDEN` / `RULE_DENIED`                    | 授权是否被取消？集合是否在 `data.collections` 里？记录规则是否允许？详见 [状态与错误码](status-codes.md)                                                       |
| 云函数访问不到字段                                   | provider 的 `permissions.data[].fields` 写了且包含该字段吗？`actions` 允许这个操作吗？                                                                        |
| 用户之间看不到彼此数据                               | 集合是私有的（默认）。需要共享就在**创建集合之前**声明 `shared_collections` / `partition: "shared"`                                                           |
| 前端调用后台能力 `BACKGROUND_CAPABILITY_UNAVAILABLE` | 没有任何已启用的后台能力——在应用窗口「权限」里勾选并重新加载（旧 SDK 报 `UNSUPPORTED_OPERATION`）                                                             |
| 云函数 `FUNCTION_RELEASE_REQUIRED`                   | 在应用窗口「权限」里允许后台运行（重新保存一次），或在「版本管理」切换一次版本，平台自动补签并绑定；仍出现请联系平台管理员检查签名密钥 / 信任配置，或重新上传 |
| 更新版本后后台任务不跑了                             | 应用中心更新时权限变宽的能力需重新确认；CLI `update` 会停用全部后台能力                                                                                       |
| 跨应用调用失败                                       | 普通 SDK 不支持跨应用调用                                                                                                                                     |
