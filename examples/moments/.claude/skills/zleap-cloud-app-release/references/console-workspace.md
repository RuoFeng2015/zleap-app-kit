# 工作区概览

「**概览**」是控制台的首页。它有两种形态：

- **开通清单**：清单步骤还没全部完成时显示，告诉你下一步做什么，并把主按钮放在当前这一步上；
- **资源卡片**：清单全部完成后显示，汇总各资源状态。

两种形态右侧 / 下方都有「**环境体检**」。

## 开通清单

页面标题：还没创建环境时是「**为 {应用名} 开通云端能力**」，开始之后是「**还差几步就能用上云端能力**」。

说明：

> 按顺序完成下面的步骤。完成后应用就能通过 Cloud SDK 读写数据和文件；带云函数的版本由平台自动签名，在应用窗口「权限」里允许后台运行即可。

清单是**数据三步**：

| #   | 步骤             | 分组 | 什么时候算完成                               |
| --- | ---------------- | ---- | -------------------------------------------- |
| 1   | **创建开发环境** | 数据 | 当前环境类型已有一个活跃（「已登记」）的环境 |
| 2   | **开通数据库**   | 数据 | 数据库状态为「已就绪」                       |
| 3   | **创建集合**     | 数据 | 开发环境里至少有一个集合                     |

推进规则：

- 按顺序推进，同一时刻只有一步是「当前步骤」（带主按钮），后面的步骤显示为灰色等待；
- 已完成的步骤打勾；开通失败的步骤显示警示图标。

（截图：开通完成后的就绪视图，见文档站）

数据三步都完成后的就绪视图：四张资源卡（数据库、文件存储、云函数、日志）和「环境体检」。还有步骤没完成时，这里显示的是开通清单。

### 第 1 步：创建开发环境

| 状态               | 说明文字                                                                       | 操作                                                        |
| ------------------ | ------------------------------------------------------------------------------ | ----------------------------------------------------------- |
| 当前               | 开发环境是只属于你的调试空间，数据与生产环境完全隔离。创建后会自动开通数据库。 | 「来源版本」下拉框（如 `v1.0.0`）+ 按钮「**创建开发环境**」 |
| 当前（无可用版本） | 没有你有权管理的活跃应用版本。                                                 | 无按钮——先去 [应用中心上传应用包](app-center-publish.md)      |
| 完成               | 已创建 · {日期}                                                                | —                                                           |

「**来源版本**」是登记环境时关联的应用版本，默认选最新的一个。点按钮会弹出确认框，内容：

> 创建开发环境后会自动开通数据能力，资源就绪前可在此查看进度。生产环境不继承开发数据或授权。

确认后：

1. 环境被登记（环境卡片显示「**已登记**」）；
2. 数据库**自动开始开通**，第 2 步进入「开通中」。

结果不明确时，这一步下方会出现提示：

| 提示                                                                                                   | 含义 / 处理                                                        |
| ------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------ |
| **尚未确认创建结果，请先刷新环境列表。**（按钮「**检查结果**」）                                       | 网络中断，不知道是否创建成功。点「检查结果」重新读取环境列表       |
| **已读取当前环境；先前创建请求仍未获确认。**                                                           | 列表里读到了环境，但这只证明「现在有环境」，不证明刚才那次请求成功 |
| **环境创建请求已被拒绝** —— 请检查当前发布者权限和所选版本。读取到已有环境不会将此次拒绝改为创建成功。 | 服务端明确拒绝                                                     |

> **不要重复点「创建开发环境」**（注意）
>
> 结果待确认时按钮会被禁用。先点「检查结果」，确认状态后再决定下一步。

> **通常已经自动完成**（提示）
>
> 声明了数据集合的应用，**安装时平台会自动创建开发环境**并开通数据库，打开控制台时这一步一般已经打勾。
> 只有没声明集合、或环境被停用时才需要手动创建。

> **生产环境**（提示）
>
> 部署开放生产环境、并在侧栏切到「生产环境」时，这一步的按钮会变成「创建生产环境」。
> 但大多数情况下不需要在这里手动创建：
>
> - 带云资源的版本第一次「发布为线上版本」时，平台会自动完成**应用级**的生产准备（生产环境、签发生产候选、生产门禁、生产库与生产集合），
>   不依赖任何人的安装，也不要求上传者正在使用这个版本。只用宿主能力的应用直接发布即可。
>   `zleap-app prepare` 通常不需要，只在 `zleap-app diagnose` 提示 `next_action: app_prepare` 时兜底使用；它只准备开发环境，不会碰生产。
>
> 各面板在生产环境下能做什么，见 界面总览 · 环境切换（文档站 /console/overview#环境标签与环境切换）。

### 第 2 步：开通数据库

| 状态   | 说明文字                                                        | 操作                             |
| ------ | --------------------------------------------------------------- | -------------------------------- |
| 当前   | 创建环境后自动开始。如果没有开始，可以手动开通。                | 「**开通数据库**」→ 跳到数据库页 |
| 开通中 | 正在分配资源并检查数据服务，通常 1 分钟内完成，完成后自动更新。 | 无（页面每 3 秒自动刷新状态）    |
| 失败   | 开通没有成功。重试会继续原来的开通请求，不会重复创建资源。      | 「**查看并重试**」→ 跳到数据库页 |
| 完成   | 已就绪                                                          | —                                |

数据库只有在**资源分配**和**数据服务探测**都成功后才显示「已就绪」。状态「暂不可用」（基础服务未就绪）也按失败显示。
具体的开通 / 重试操作在数据库页完成，见 数据库 · 开通状态（文档站 /console/database#数据库开通状态）。

### 第 3 步：创建集合

集合**不能在控制台里新建**，它由应用 Manifest 的 `data` 声明，数据库就绪后服务端按声明自动创建。

| 状态                    | 说明文字                                                                               | 操作                                             |
| ----------------------- | -------------------------------------------------------------------------------------- | ------------------------------------------------ |
| 当前（Manifest 有声明） | Manifest 声明了 {n} 个集合，通常会自动建好；没有出现时点同步。（下方列出声明的集合键） | 「**同步集合**」→ 跳到数据库页                   |
| 当前（Manifest 无声明） | 这个版本的 Manifest 没有声明集合。在 data.collections 中声明后重新发布。               | 「**查看如何声明**」→ 跳到数据库页（有示例片段） |
| 完成                    | 已有 {n} 个集合                                                                        | —                                                |

> **「声明了哪些集合」读的是你**当前安装**的版本**（注意）
>
> 控制台取的是你本人当前安装版本的 Manifest（`data.schemas` 的键）。如果你还没安装这个应用，或装的是旧版本，
> 这里可能显示「没有声明集合」。先在应用中心安装 / 更新到包含声明的版本。

如果你的 Manifest 确实没有 `data`——即应用不用云数据库——这一步无法完成。
声明方法见 Manifest v2 配置（文档站 /reference/manifest） 的「data — 数据集合」一节。

> **云函数不需要单独签名或激活**（提示）
>
> 带后台能力的版本上传时由平台自动签名；安装、切换版本、在应用窗口「权限」里允许后台运行时，缺签会自动补签并绑定。
> 后台能力仍需使用者本人在应用窗口「权限」里勾选「允许后台运行」。

### 右侧：环境卡片

清单右侧是当前环境的资源卡片，标题随所选环境显示「**开发环境**」或「**生产环境**」；环境已登记时带「**已登记**」标签：

| 资源       | 状态来源                                                                                 |
| ---------- | ---------------------------------------------------------------------------------------- |
| 业务数据库 | 数据库状态                                                                               |
| 文件存储   | 数据库就绪即「已就绪」，否则「暂不可用」                                                 |
| 云函数     | 应用有「已就绪」的签名发布时为「已就绪」，否则「未分配」（无法识别的值显示「暂不可用」） |
| 应用日志   | 同上                                                                                     |

状态取值见 界面总览 · 资源状态（文档站 /console/overview#资源状态）。还没有环境时显示「尚未创建环境」，读取中显示「正在读取…」。

## 环境体检

「**环境体检**」逐层检查从部署配置到已建集合的整条链路，找出**第一个出问题的地方**。
它不会自动运行，点「**运行体检**」才发请求；跑过之后按钮变为「**重新检查**」。没有环境时按钮不可用。

结果摘要：全部通过时「**各层检查都通过了**」；否则「**「{检查项}」未通过**」。

环境体检跑完后：全部通过时显示「各层检查都通过了」，按钮变为「重新检查」。

- 开通清单视图里是精简卡片：只给摘要，并在下方展开第一个未通过项的详情；
- 资源卡片视图里是完整卡片：逐行列出每一项（✓ 通过 / ⚠ 未通过）及其详情。

检查项（按顺序）：

| 层  | 检查项         | 检查什么                                | 未通过时                                                          |
| --- | -------------- | --------------------------------------- | ----------------------------------------------------------------- |
| L0  | 数据面地址     | 部署是否配置了数据服务地址              | **平台配置问题**，联系管理员                                      |
| L0  | 数据面密钥长度 | 数据服务密钥是否足够长                  | 平台配置问题，联系管理员                                          |
| L0  | ops 地址/令牌  | 资源编排服务是否配置                    | 平台配置问题，联系管理员                                          |
| L1  | 核心库记录     | 这个应用的数据库记录是否存在且「ready」 | 「不存在（尚未开通）」→ 回到第 2 步开通；其他状态看详情里的错误码 |
| L1  | 环境记录       | 当前环境是否存在且为活跃状态            | 环境被停用或不存在                                                |
| L1  | 绑定记录       | 你本人与这个环境的数据绑定是否已建立    | 「尚未建立（开通中属正常）」；其他错误原因见详情                  |
| L1  | 声明的集合     | 能否从你的安装解析出声明的集合          | 解析失败通常是**应用没有声明数据能力**或你还没安装该应用          |
| L2  | ops 台账       | 资源分配台账是否为 ready                | 资源分配未完成或失败                                              |
| L3  | ops 准入       | 数据服务是否允许这个应用写入            | 准入被拒时，应用运行时写入会失败                                  |
| L4  | 数据面探测     | 数据服务对这个应用的探测是否就绪        | 平台侧（白名单 / 密钥 / 容器）问题，联系管理员                    |
| L5  | 已建集合       | 实际已创建的集合                        | 「(空)」→ 到数据库页「同步 Manifest 中的集合」                    |

L2、L3 只在资源编排服务已配置时检查；L4、L5 只在绑定记录存在且数据服务地址已配置时检查。

> **怎么用体检区分「平台问题」和「我的问题」**（提示）
>
>
> - **L0、L2–L4 失败**：几乎都是部署或平台侧问题，你在应用里改代码没用。把体检结果和「环境信息」里的环境 ID 发给管理员。
> - **L1「声明的集合」、L5「已建集合」失败**：多半是 Manifest 没声明 `data`、没安装 / 没更新到对应版本，或集合还没同步——这是你可以自己处理的。
>

> **注意**（注意）
>
> 体检说明文字写「逐层检查权限、环境、数据库和函数运行时」，但当前实现**没有**检查函数运行时。
> 云函数是否可用，以「云函数」页和函数调用结果为准。

## 常见问题

### 第 1 步没有「创建开发环境」按钮

说明文字是「没有你有权管理的活跃应用版本。」——你还没有这个应用的有效版本。先去应用中心上传应用包。

### 数据库一直「开通中」

页面每 3 秒自动检查一次，通常 1 分钟内完成。长时间不变或变成「失败」时，到数据库页「重试开通」，并运行环境体检看卡在哪一层。

### 集合那一步一直完成不了

- 确认 Manifest 的 `data.collections` / `data.schemas` 里有声明；
- 确认你**安装**的就是带声明的版本（控制台读的是安装版本的 Manifest）；
- 到数据库页点「同步 Manifest 中的集合」；
- 仍然不行就运行环境体检，看 L1「声明的集合」和 L5「已建集合」。
