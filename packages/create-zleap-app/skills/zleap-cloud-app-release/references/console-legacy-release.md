# 版本与激活（旧 app_key 应用）

> **只适用于旧应用**（注意）
>
> 本页只适用于用旧 `app_key` 命名空间上传的应用（包括它们上传应用包时自动登记的发布候选）。
> 在控制台「创建应用」得到 `appid`（`zl…`）的应用，上线统一用「[版本管理](console-release.md#版本管理)」，不需要签名、激活、门禁这些步骤。
> appid 应用在开发环境里要跑云函数时，用的是「版本管理」页下方的同名区块「**开发环境：云函数激活**」，
> 操作步骤与本页相同，但入口不在本页。

## 概览

控制台侧边栏的「**版本与激活**」页（下文也叫发布版本页）负责把一个**应用包版本**变成**可运行的已签名发布**，
再把它**激活**到你的安装上。页头说明：

> 「云函数只运行签名并激活的版本。上传新版本后，在这里签名并激活到开发环境。」

先认识几个名词：

| 名词                    | 解释                                                                                                                                                                           |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **发布候选**（release） | 针对「某个版本 + 某个应用包」登记的一条发布记录。刚创建时是草稿，签名验证通过后变为「已就绪」。                                                                                |
| **签名证明**            | 一个 JSON 信封，用部署的 Ed25519 私钥对应用包字节、Manifest、来源和审核信息签名。服务端验签通过，候选才会就绪。                                                                |
| **激活**                | 把一个已就绪的发布**绑定到安装**上（安装记录里的 `release_id`）。云函数（`managed_function`）只在安装绑定了已就绪发布时执行。                                                  |
| **激活代数**（epoch）   | 安装上的一个计数器，每次绑定变化都会加一。激活请求要带上当前值，用来防止两个窗口同时切换版本；值过期时请求会被拒绝（刷新后重试即可）。安装从未绑定过发布时，首次激活可以不带。 |

> **什么时候需要这一页**（提示）
>
>
> - 只用 Cloud SDK 读写**数据库和文件**：不需要签名和激活（开通清单里「使用云函数或后台任务时需要」一组可以跳过）。
> - 开发环境里用到 **Node 云函数**（provider 类型 `managed_function`，包括 `callFunction` 和以它为执行方的后台能力）：必须签名并激活，否则返回 `FUNCTION_RELEASE_REQUIRED`。
> - `logic_unit`、`builtin` 类型的后台能力在开发环境不要求绑定发布；**生产环境**的所有后台能力都要求绑定发布。
>

## 发布流程（三步卡片）

页面最上方是「**发布流程**」三步卡片，当前所在的一步会高亮：

| 步骤           | 卡片说明                                                                 |
| -------------- | ------------------------------------------------------------------------ |
| 1 **新建候选** | 选择应用包，填写来源信息。此时候选是草稿，还不能激活。                   |
| 2 **签名验证** | 服务端用部署私钥对包签名，验签并逐字节比对制品。通过后候选变为「就绪」。 |
| 3 **激活开发** | 把就绪候选绑定到你的安装。此步之后后台能力才会真正执行。                 |

卡片标题下的说明因身份而不同：

- 普通发布者：「三步走完，Node 云函数与 callFunction 才能在开发环境执行。第 2 步由服务端持钥完成，你无需管理私钥。」
- 系统管理员：「你是系统管理员：也可代其他发布者完成第 2 步的签名。」

有就绪候选、但它还没有绑定到你的安装时，第 3 张卡片里直接给出「**激活开发**」按钮（激活的是**最新一条已就绪**的候选）。
没有可用安装时按钮不可点，下方提示「**需要先安装该应用（当前没有可用的安装）**」。

激活完成后，第 3 张卡片显示：「激活已把这个签名版本绑定到你的安装。声明了后台能力的应用需要先允许至少一项后台能力（应用窗口「Cloud 数据授权」或「云函数」页）才能激活；之后在「云函数」页切换授权会解除绑定，需要重新激活。」
这句提示的前半句已经过时：**激活不再要求先允许后台能力**（文中的「Cloud 数据授权」即现在应用窗口的「权限」）；后半句（切换授权会解除绑定）仍然成立。

> **推荐顺序**（提示）
>
> 激活和允许后台运行没有先后要求，但两者都完成后台能力才会执行。推荐顺序是：先签名，再在应用窗口「权限」里勾选后台能力
> （已有就绪发布时，保存会自动绑定发布），最后回这里核对或点「激活开发」。激活到还没有的环境时，平台会自动创建该环境。

## 环境提示

三步卡片下方有一条提示，内容取决于部署是否开放了生产环境：

| 部署状态   | 提示标题           | 提示内容                                                                                                                                 |
| ---------- | ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------- |
| 生产未开放 | **发布验证**       | 开发环境激活会绑定当前安装的已验证版本；生产环境发布仍未开放。                                                                           |
| 生产已开放 | **生产环境已开放** | 生产环境面向全体使用者。激活到生产需要通过生产门禁（签名证明、策略绑定、审批窗口与当前信任根）；通过后该应用的使用者读取的是生产数据域。 |

生产是否开放由**部署**决定，不是你能在控制台里打开的开关，见下文[激活到生产](#激活到生产)。

## 候选从哪来

### 上传时自动生成的草稿

在应用中心「上传应用包」时，服务端会在同一事务里为这个版本和应用包**自动登记一条草稿候选**
（来源类型为「上传的应用包」，来源引用是应用包编号，凭据编号为 `pending-signature`）。
所以多数情况下你**不需要手动新建候选**，直接对这条草稿点「验证并签发」即可。

部署没有配置发布信任策略时，自动登记会被跳过（上传本身不受影响），这时列表里没有草稿，也无法签名。

> **用 zleap-app CLI 发布的包**（提示）
>
> `zleap-app publish` 同样可以发布含 `cloudfunctions/` 的包，校验规则与应用中心「上传应用包」一致，
> 见[上传与发布应用](app-center-publish.md)。

### 手动新建发布候选

点击「**新建发布候选**」展开表单（再点「**收起表单**」折叠）。表单说明：

> 「选择应用包，补充来源和验证信息后创建候选。新建候选不会启动或发布应用。」

「新建发布候选」按钮只在你有可管理的应用包版本时可用；没有时显示「**没有可管理的应用包版本。**」
（列表只包含**你本人上传**、当前有效的应用包。）

#### 选择发布来源

| 字段                 | 说明                                                                       |
| -------------------- | -------------------------------------------------------------------------- |
| **来源版本与应用包** | 下拉选择版本，显示为「版本号 · 应用包编号」，默认第一个                    |
| **来源类型**         | **上传的应用包** / **Git 构建**                                            |
| **来源引用**         | 必填。占位文字是所选应用包的编号（没有时为「包或构建引用」），需要手动填写 |

来源类型选「**Git 构建**」时多出两个字段：**Commit**（生成此包时实际使用的提交编号）和**构建 ID**（构建系统的任务编号）。
服务端要求 Git 构建**两者都填**；选「上传的应用包」时不能带这两个字段。

#### 配置验证信息

| 字段                 | 说明                                  |
| -------------------- | ------------------------------------- |
| **凭据编号（自动）** | 只读。自动填入 `proof-{签名密钥编号}` |
| **策略版本（自动）** | 只读。自动填入当前部署的发布策略版本  |

两个字段下方注明来源：「由当前部署自动填入：部署 {deployment} · 签名密钥 {key}。」
它们来自部署的信任配置，**不需要也不能手填**。读不到信任配置时两个字段为空，提交会提示「请填写版本、证明、策略、来源和请求 ID。」——这属于部署未配置，不是你填错了。

#### 高级请求设置

折叠在「**高级请求设置**」里：

| 控件                | 说明                                           |
| ------------------- | ---------------------------------------------- |
| **请求 ID（幂等）** | 页面自动生成，用于识别同一次提交，避免重复创建 |
| **生成新的请求 ID** | 换一个编号                                     |

> **请求 ID 的错误用法**（危险）
>
> 看到「请求结果尚未确认」就点「生成新的请求 ID」重新提交——这会绕过幂等保护。
> 结果未知时页面会锁住表单并保留原请求 ID，请点错误提示里的「**查询原请求**」确认结果。
> （同一个请求 ID 换了内容再提交会被服务端拒绝。）

#### 提交

点「**创建发布候选**」。成功后表单自动收起，列表刷新。

> **同一个应用包不会堆出多条草稿**（提示）
>
> 同一版本、同一应用包已有未完成的候选（草稿 / 校验中 / 出错）时，服务端会**更新那条候选**而不是再建一条。

失败提示（页面顶部）：

| 提示                                         | 含义                                       |
| -------------------------------------------- | ------------------------------------------ |
| 请填写版本、证明、策略、来源和请求 ID。      | 有必填项为空（或信任配置读不到）           |
| 发布候选请求被拒绝。                         | 服务端明确拒绝                             |
| 请求结果尚未确认，请查询原请求。             | 结果未知，带「查询原请求」按钮             |
| 请求已保留：{请求ID}。请查询原请求后再继续。 | 显示在提交按钮旁，提醒表单已锁定在原请求上 |

## 发布记录

标题「**发布记录**」，说明「查看候选状态，验证签名或检查生产发布条件。」右上角有「**刷新**」。
没有记录时显示「**尚无发布候选。**」，每页 20 条，超过一页时出现「上一页 / 第 n / m 页 / 下一页」。

每条候选显示：

- 「**候选 #{编号}**」和状态标签；
- 「来源版本 {版本号}」；
- 可展开的「**包校验值**」，里面是完整的包校验值（sha256）和请求 ID；
- 出错时以红字显示错误码；本次会话刚激活的候选会显示「**已激活开发**」/「**已激活生产**」。

存在已就绪发布时，列表上方还会显示一块[使用者升级情况](#使用者升级情况)摘要。

### 候选状态

| 状态         | 标签       | 含义                   |
| ------------ | ---------- | ---------------------- |
| `draft`      | **草稿**   | 已登记，尚未签名验证   |
| `validating` | **校验中** | 验证进行中             |
| `ready`      | **已就绪** | 签名验证通过，可以激活 |
| `disabled`   | **已撤回** | 已撤回，不能再激活     |

### 每条候选的操作

| 按钮               | 出现时机                 | 作用                         |
| ------------------ | ------------------------ | ---------------------------- |
| **验证并签发**     | 草稿 / 校验中            | 服务端持钥签名并验签（推荐） |
| **验证签名证明**   | 草稿 / 已就绪            | 粘贴外部生成的签名证明 JSON  |
| **激活开发**       | 已就绪                   | 绑定到你在开发环境的安装     |
| **激活到生产**     | 已就绪，且部署已开放生产 | 通过生产门禁后绑定到生产     |
| **查看生产门禁**   | 已就绪                   | 查看生产门禁评估             |
| **撤回**（危险色） | 未撤回                   | 撤回候选                     |

## 验证并签发

对草稿点「**验证并签发**」，确认框：

> **为该候选签发发布证明？**
>
> 服务端将使用部署私钥签名，并走与手动提交完全相同的验签流程。私钥不会离开服务器。

确认后服务端读取应用包字节，生成签名证明，再按「验证签名证明」同样的规则验签。通过后候选变为「**已就绪**」。

- 发布者可以签发**自己的**候选。页头的「你是系统管理员：也可代其他发布者完成第 2 步的签名」描述的是系统管理员的能力；
  但本页的发布记录只查询**当前发布者（你）名下**的候选，所以在这个页面里看不到、也点不到他人的候选，代签没有入口。
- 只有草稿 / 校验中的候选能签发；已就绪的候选不能重新签。
- 服务端签发的证明里，审批有效期为**签发后 7 天**（若签名密钥更早到期则以密钥到期为准）。这会影响[生产门禁](#生产门禁)的「审批窗口」检查。
- 部署没有配置签名密钥或信任策略时无法签发（`RELEASE_TRUST_UNAVAILABLE`），需要部署管理员处理，不是你的包有问题。

## 验证签名证明

适用于由**外部可信发布器**生成签名证明的场景。点「**验证签名证明**」打开对话框「**验证发布证明**」：

- 范围行：「发布 {release} · 版本 {version} · 包 {package}」，下方可展开包校验值；
- 说明：「粘贴可信发布器生成的签名证明信封 JSON。服务端会校验签名、信任密钥、策略审核、包字节、Manifest 以及精确发布范围。最多 2 MiB。」
- 「**签名证明 JSON**」文本框，或点「**选择 JSON 文件**」读入 `.json` 文件；
- 按钮「**验证证明**」/「**关闭**」，结果未知时变成「**查询原结果**」。

验证中显示「正在验证签名证明…」。成功后显示：

> **签名与包证明已验证，候选已就绪。**
>
> 验证不会开放生产环境；验证成功后请在发布列表点击「激活开发」。

提交前，页面会先在本地检查 JSON 结构（`zleap.release-proof/1` 协议、Ed25519、身份字段）以及它是否对应**当前这条候选**
（应用、发布、版本、包、发布者、部署、包摘要、策略版本、来源）；对不上直接提示「范围不匹配」，不会发请求。

失败提示：

| 类别                | 提示                                                                                 | 属于哪类问题                 |
| ------------------- | ------------------------------------------------------------------------------------ | ---------------------------- |
| `tooLarge`          | 证明文件超过 2 MiB 限制。                                                            | 你的输入                     |
| `invalid`           | 证明 JSON 或签名信封无效。                                                           | 你的输入                     |
| `scopeMismatch`     | 证明与当前应用、发布、包、来源、摘要或策略不匹配。                                   | 证明不是为这条候选生成的     |
| `signatureInvalid`  | 无法验证发布签名。                                                                   | 签名错误或密钥不对           |
| `artifactMismatch`  | 签名 Manifest 或包制品清单不匹配。                                                   | 签名的不是这个包             |
| `policyStale`       | 策略审核已过期或不再当前。                                                           | 审批过期或部署策略已更新     |
| `policyUnavailable` | 尚未配置发布策略，无法验证。                                                         | **平台未配置**               |
| `trustUnavailable`  | 发布信任策略尚未配置，或发布者密钥不可用、已撤销或已过期。请由管理员检查配置后重试。 | **平台未配置**或密钥失效     |
| `disabled`          | 此发布候选已撤回。                                                                   | 候选已撤回                   |
| `rejected`          | 签名证明验证请求被拒绝。                                                             | 其他拒绝                     |
| `unknown`           | 结果未确认，已保留原发布与签名证明。请查询原结果，确认前不会重复提交。               | 网络等原因，点「查询原结果」 |

## 激活开发

对已就绪的候选点「**激活开发**」（或三步卡片里的同名按钮），确认框：

> **激活到开发环境？**
>
> 只会登记开发环境激活门禁，不会开放生产发布。

成功后按钮变成「**已激活开发**」，安装的激活代数加一，开通清单的「升级安装并激活」一步标为「已激活到开发环境」。
激活后请**重新加载应用**，旧的 Cloud 会话会因发布变化失效（`RELEASE_UNAVAILABLE`），宿主会自动重开会话并重试一次。

### 激活的前置条件

| 条件                                                 | 不满足时                                                                                                                |
| ---------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| 你**安装了**这个应用（个人安装）                     | 按钮不可点，提示「需要先安装该应用（当前没有可用的安装）」；服务端为 `RELEASE_ACTIVATION_SCOPE_REQUIRED`                |
| 安装的**版本和应用包**正是这条候选的版本和应用包     | `RELEASE_VERSION_SWITCH_UNAVAILABLE`：请改用[升级安装并激活](#升级安装并激活)                                           |
| 对应环境存在，或能自动创建（生产需部署已开放）       | 自动创建失败时 `RELEASE_ACTIVATION_UNAVAILABLE`；生产未开放时 40300「本部署未开放生产环境」                             |
| 候选已就绪、带签名证明                               | `RELEASE_NOT_READY` / `RELEASE_DISABLED` / `RELEASE_PROOF_UNAVAILABLE`                                                  |
| 激活时服务端会**用当前信任策略重新验签**并比对包字节 | `RELEASE_POLICY_STALE`、`RELEASE_IDENTITY_MISMATCH`、`RELEASE_ARTIFACT_MISMATCH` 等：部署策略已变化，需新建候选重新签名 |
| 声明了云函数时，候选要有函数运行快照                 | `FUNCTION_RUNTIME_SNAPSHOT_REQUIRED`                                                                                    |
| 激活代数没有被别处改变                               | `ACTIVATION_EPOCH_STALE`：刷新控制台后重试                                                                              |

被拒绝时页面顶部显示「**发布候选请求被拒绝。**」，下面附带上表中的原因码。

> **「当前应用安装未就绪」**（注意）
>
> 如果控制台没读到你的安装或激活代数，点激活会提示：
> 「当前应用安装未就绪，无法激活开发：控制台没有读到可用安装或激活代数。请刷新后重新选择该应用（应用需处于已安装状态）再试。」
> 这时**没有发出任何请求**，先去应用中心安装该版本。

### 其他会自动绑定发布的操作

除了「激活开发」，下面几种操作也会把安装绑定到**该版本最新一条已就绪发布**：

- 在应用中心**安装**或**更新**到某个版本（该版本有已就绪发布时）；
- 控制台概览的「**升级到 {版本} 并激活**」（见下一节）；
- 在应用窗口「**权限**」里勾选后台能力并「保存并重新加载」。

反过来，在控制台[云函数 · 后台能力](console-functions.md#授权)里点「允许后台运行」「撤销授权」「重新授权」会**解除**安装上的发布绑定，
之后 Node 云函数需要重新「激活开发」。

## 升级安装并激活

这个入口在控制台**概览**的开通清单里（「使用云函数或后台任务时需要」一组的第二步「**升级安装并激活**」）。
当最新的已就绪发布对应的版本**不是**你当前安装的版本时，步骤说明为：

> 当前安装的是 v{installed}，升级到已签名的 {version} 后，云函数即可运行。

按钮「**升级到 {版本} 并激活**」。点击后：

1. 先做**升级预检**。不能升级时显示「**现在不能升级**」和原因（没有原因时为「请检查版本状态后再试。」）。
2. 弹出确认框「**升级到 {版本} 并激活？**」，正文「安装会切换到这个已签名版本，开发环境的云函数随即使用它。生产环境不受影响。」，
   并逐行列出能力变化：「沿用的授权：…」「需要重新同意：…」「不再需要：…」。
3. 确认后升级安装，并把安装绑定到目标版本的已就绪发布（升级即激活）。

| 结果               | 提示                                                                                                                      |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------- |
| 网络中断、结果未知 | 「**升级结果待确认**」：网络中断，升级可能已经完成。再点一次会继续同一个请求，不会重复升级。按钮变为「继续升级到 {版本}」 |
| 被拒绝             | 「**升级没有完成**」：安装版本可能已在别处变化，刷新后重试。                                                              |

安装版本已经等于签名版本、只是还没绑定时，这一步的按钮是「**去激活**」，跳到本页用「激活开发」完成。

## 撤回

点「**撤回**」，确认框：

> **撤回此发布候选？**
>
> 撤回后候选不可再激活，但原请求和回执仍可查询。

> **正在使用的发布不能撤回**（危险）
>
> 只要还有任何安装绑定在这条发布上，撤回会被拒绝（`RELEASE_ACTIVE`）。撤回是不可逆的：已撤回的候选不能再签名或激活，只能新建候选。

## 使用者升级情况

存在已就绪发布时，页面会在发布记录列表**上方**显示**最新一条已就绪发布**的使用情况：

- 标题「**最新发布 {版本} 的使用情况**」；
- 「{n} 个安装已在此版本」「{n} 个安装仍在旧版本」，有未记录版本的安装时还有「{n} 个安装没有版本记录」；
- 仍在旧版本的安装按版本列出（最多 5 行），如「1.0.0：3 个安装」。

统计的是该应用所有有效安装的**版本分布**（不区分个人或空间），只有发布者本人或系统管理员能查看。

## 生产门禁

对已就绪候选点「**查看生产门禁**」，打开「**生产门禁评估**」对话框，显示「发布候选 {编号}」、结论标签和「通过 {n} 项 · 阻断 {n} 项」。
存在阻断项时出现「**生产激活仍被阻断**」，列出阻断原因。底部有「**刷新**」「**关闭**」，读不到时显示「暂时无法读取生产门禁。」

结论标签：

| 标签                   | 含义                                           |
| ---------------------- | ---------------------------------------------- |
| **等待 Provider 复核** | 所有检查通过、服务端允许激活（可以激活到生产） |
| **已阻断**             | 至少一项检查未通过                             |
| **不可用**             | 门禁数据不完整                                 |

检查项（每项标「通过」或「阻断」，阻断时附原因码）：

| 检查项                 | 通过条件                                                        | 阻断原因码                                                     |
| ---------------------- | --------------------------------------------------------------- | -------------------------------------------------------------- |
| `release_ready`        | 候选已就绪                                                      | `RELEASE_NOT_READY`                                            |
| `signed_attestation`   | 有签名证明且已验签                                              | `RELEASE_PROOF_UNAVAILABLE`                                    |
| `approval_window`      | 当前时间处于证明的审批窗口内（审批时间 ≤ 现在，且早于到期时间） | `RELEASE_APPROVAL_EXPIRED_OR_MISSING`                          |
| `policy_binding`       | 审批绑定的策略版本与候选一致                                    | `RELEASE_POLICY_STALE`                                         |
| `current_trust_policy` | 签名密钥仍启用、部署与策略版本仍是当前、签发时间在密钥有效期内  | `RELEASE_TRUST_UNAVAILABLE`                                    |
| `runtime_snapshot`     | 声明了云函数时，候选有函数运行快照                              | `FUNCTION_RUNTIME_SNAPSHOT_REQUIRED`                           |
| `production_provider`  | 部署配置了本地生产发布授权且信任根可加载                        | `PRODUCTION_RELEASE_UNAVAILABLE` / `RELEASE_TRUST_UNAVAILABLE` |

审批信息行：「审批 {审批编号} · 到期 {到期时间}」。

> **审批窗口过期怎么办**（提示）
>
> 用「验证并签发」得到的证明，审批窗口最长 7 天。过期后这条候选无法再进生产，也不能重新签发（已就绪的候选不能再签）。
> 用「新建发布候选」为同一个应用包建一条新候选，再「验证并签发」即可。

## 激活到生产

> **是否可用取决于部署**（注意）
>
> 「**激活到生产**」按钮只在部署**开放生产环境**时出现：部署的发布信任配置就绪即开放（由运维在部署时自动配置），
> 没有单独的开关。信任配置未就绪时生产环境在控制台任何入口都不出现，这是**平台未开放**，不是你的应用有问题。

部署开放生产后：

1. 确认这条候选的[生产门禁](#生产门禁)全部通过。生产环境不需要预先创建：激活时不存在会自动创建（也可以在控制台概览手动创建）。
2. 点「**激活到生产**」，确认框：

   > **激活到生产环境？**
   >
   > 生产激活必须通过生产门禁；未通过时不会落库，并会给出未通过的具体原因。

   服务端会**重新评估门禁**，任何一项未过都拒绝，并在「发布候选请求被拒绝。」下方给出第一个阻断原因；
   部署未开放时原因为 `PRODUCTION_RELEASE_UNAVAILABLE`。成功后按钮变为「**已激活生产**」。

3. **开通生产集合**：激活只创建环境、不建集合。到控制台切到「生产环境」→「数据库」开通（会按声明建集合）；
   否则应用切到生产数据域后报 `COLLECTION_NOT_FOUND`。用 `zleap-app prepare` 会一并完成这一步。
4. 有后台能力时，在应用窗口的「权限」（此时作用于生产数据域）勾选要运行的后台能力。

生产开放后，其他使用者一律使用生产数据域；应用有了生产环境后，发布者自己也使用生产数据域。生产环境中的后台能力必须绑定已就绪发布才会执行。

> **生产激活影响全体使用者**（危险）
>
> 生产数据域面向全体使用者。激活前请先在开发环境用同一版本完整验证，并确认门禁里的审批与策略信息。

## 常见问题

### 签名之后云函数还是报 `FUNCTION_RELEASE_REQUIRED`

签名只让候选「就绪」，还要**激活**（绑定到安装）。检查：

1. 「发布流程」第 3 步是否已完成；
2. 激活之后是否又在控制台「允许后台运行 / 撤销授权 / 重新授权」——这些操作会解除绑定，需要再点一次「激活开发」；
3. 激活后是否重新加载了应用。

### 「激活开发」提示安装版本对不上（`RELEASE_VERSION_SWITCH_UNAVAILABLE`）

激活只绑定**你已安装的那个版本**。你装的是旧版本时，用概览里的「升级到 {版本} 并激活」，或在应用中心更新到该版本。

### 列表里没有自动生成的草稿

部署没有配置发布信任策略时上传不会自动登记草稿，「新建发布候选」表单里的凭据编号和策略版本也会为空。请联系部署管理员；这不是包的问题。

### 「验证签名证明」的 JSON 从哪来

由**可信发布器**用部署信任的密钥生成，签名必须能被服务端验证。大多数开发者直接用「**验证并签发**」，不需要自己准备这个文件。

### 创建候选或验证成功后应用会被发布吗

不会。「新建候选不会启动或发布应用」；验证只让候选就绪，要激活才会绑定到安装。让其他用户安装请走[应用中心发布](app-center-publish.md)。
