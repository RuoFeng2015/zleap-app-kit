# 创建应用与成员管理

开发一个新应用，第一步是在云开发控制台**创建应用**、拿到平台生成的 `appid`；团队一起开发时，
由管理员在「**成员**」里把同事加为开发者。

> **一句话流程**（提示）
>
> 控制台「创建应用」→ 复制 `appid` → 脚手架带上 `appid` 或写进 `manifest.json` → `npm run deploy` 上传 →
> （需要协作时）「团队」→「成员」里添加开发者 →（给全企业用时）「版本管理」里发布为线上版本。

## 创建应用

入口有两个：

- 侧栏顶部的**应用切换下拉**里点「**创建应用**」；
- 你还没有参与任何应用时，页面中央提示「你还没有参与任何应用。创建一个应用拿到 appid，或请应用管理员把你加为开发者。」，
  下面也有「**创建应用**」按钮。

打开的抽屉标题为「**创建应用**」，副标题「平台会生成 appid，你自动成为管理员」：

| 字段             | 说明               |
| ---------------- | ------------------ |
| 应用名称         | 必填，最多 64 个字 |
| 应用说明（可选） | 最多 2000 字       |

抽屉底部提示「创建后把 appid 写进 manifest 即可上传；名称和说明以后上传的 manifest 为准。」点「**创建**」完成。

创建后：

- 平台生成 `appid`，形如 `zl3f9a2c7e1b0d4a68`（`zl` + 16 位小写十六进制）。它全局唯一，**永不复用**；
- 你自动成为这个应用的**管理员**；
- 应用会出现在应用切换下拉里。

### 还没上传过代码时：开通引导页

刚创建、还没有上传过任何版本的应用，控制台不显示环境和开通清单，而是一张引导页：
「应用已创建，还没有上传过代码。按下面三步把第一个版本传上来。」

页面顶部是 `appid` 芯片，旁边是「**复制**」按钮（无障碍名称是「复制 appid」，复制后短暂显示「已复制」）。三步是：

1. **新项目：用脚手架创建，自动带上 appid**

   ```bash
   npm create zleap-app@latest my-app -- --appid zl3f9a2c7e1b0d4a68 --name "客户拜访"
   ```

   `--name` 填控制台里的应用名：发布时应用名以 `manifest.json` 的 `name` 为准，不填会用目录名（这里是 `my-app`）。

2. **已有项目：把 appid 写进 manifest.json**

   ```json
   {
     "schema": "zleap.app/2",
     "appid": "zl3f9a2c7e1b0d4a68",
     ...
   }
   ```

3. **上传开发版本**：`npm run deploy`

下方还有「一起开发？」提示：「在「成员」里把同事加为开发者，他们就能用同一个 appid 上传、在控制台管理这个应用。」
点「**去添加成员**」跳到成员页。

第一个版本上传后，再打开这个应用就是正常的控制台视图，按 工作区概览（文档站 ./workspace） 的开通清单继续；
只用宿主能力、不需要云资源的应用则是简化的概览，直接去 版本管理（文档站 /console/release#版本管理） 发布即可。

## 成员与角色

侧栏「**团队**」分组下的「**成员**」，页面说明「管理员和开发者都能上传、在控制台管理这个应用；只有管理员能增删成员。」

页面顶部是一条 appid 栏：`appid` 芯片、旁边的「**复制**」按钮，以及你在该应用里的**当前角色标签**（「管理员」或「开发者」）。

（截图：成员页，见文档站）

成员页：顶部是 appid + 复制 + 当前角色，下面是添加成员、成员行与角色、退出操作。

| 角色       | 能做什么                                                          |
| ---------- | ----------------------------------------------------------------- |
| **管理员** | 管理成员与应用：添加、移除成员，修改角色；也能上传、调试与管理    |
| **开发者** | 上传、调试与管理：用同一个 `appid` 上传版本、在控制台管理这个应用 |

控制台的应用切换下拉列出**你是管理员或开发者的全部应用**。

### 添加成员（管理员）

在「**添加成员**」里输入对方的**登录名、手机号或邮箱**，选择角色（默认开发者），点「**添加**」。
输入框下方提示「管理员：管理成员与应用；开发者：上传、调试与管理。」

| 提示                                   | 含义                                                   |
| -------------------------------------- | ------------------------------------------------------ |
| 没有找到这个用户                       | 对方还没在本企业开通账号，或登录名 / 手机号 / 邮箱写错 |
| 该账号匹配到多个用户，请改用登录名添加 | 手机号或邮箱对应了多个账号                             |
| 该用户已经是成员                       | 需要调整角色请直接修改角色                             |

### 修改角色、移除与退出

- **修改角色**（管理员）：在成员行的角色下拉里切换「管理员 / 开发者」；
- **移除**（管理员）：点成员行的「**移除**」，确认「移除 {名字}？——移除后对方不能再上传或管理这个应用，已上传的版本保留。」；
- **退出**（自己）：在自己那一行点「**退出**」，确认「退出「{应用}」？——退出后你不能再上传或管理这个应用，需要管理员重新添加。」

应用**至少要保留一位管理员**。移除、退出或降级会让应用没有管理员时，操作被拒绝：
40900「应用至少要保留一位管理员」，处理方式是先把另一位成员设为管理员，再做这个操作。

非管理员调用成员管理会得到 40300「只有应用管理员可以管理成员」。

### 上传时的成员校验

谁能上传由成员决定：

| 情况               | 结果                                                                                                                           |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------ |
| `appid` 还没创建   | 40400「appid 不存在」（`detail.reason` 为 `APP_NOT_FOUND`）：先在云开发控制台「创建应用」                                      |
| 上传者不是应用成员 | 40300「你不是这个应用的开发者」（`detail.reason` 为 `NOT_APP_MEMBER`）：请联系应用管理员在云开发控制台「成员」里把你加为开发者 |
| 管理员或开发者上传 | 正常上传                                                                                                                       |

## 成员上传的版本

用 `appid` 的应用里，每个成员上传的都是一个**开发版本**，全部列在侧栏「发布」组的「版本管理（文档站 /console/release#版本管理）」里，标出上传者和上传时间：

- 任何成员（管理员或开发者）都可以把任一成员上传的版本「发布为线上版本」，或「回退到此版本」，不要求上传者正在使用这个版本；
- 「切换到此版本」只把你本人桌面上的应用切到任一成员上传的版本，包括同事还没发布的版本（方便联调），不影响其他人，也不改变线上版本；成员从不被自动切换；
- 开发版本只对成员可见，不是成员的人看不到、也切不到。

## 用户授权

侧栏「团队」组的「**用户授权**」页（appid 应用）统计使用者通过[授权登录](app-runtime.md#授权登录)给本应用的个人信息。
页面说明是「使用者通过授权登录（zl.auth.authorize）给本应用的个人信息：只统计人数，不展示具体用户和手机号。」

| 数字                       | 含义                                       |
| -------------------------- | ------------------------------------------ |
| 已授权人数                 | 当前同意过至少一项的使用者人数             |
| 头像和昵称 / 手机号 / 邮箱 | 各项同意人数                               |
| 已撤销                     | 同意过、后来在「已授权信息」里撤销了的人数 |

只有人数，**看不到具体用户和手机号**——具体信息只在使用者本人同意后交给应用运行时。每次同意、拒绝、撤销和云函数读取都会记审计日志。
还没有人授权时显示「**还没有人授权**」，下方说明：应用调用 `zl.auth.authorize` 并且用户点了「允许」后，这里会显示人数。
接口：`GET /api/v1/app-cloud/apps/{app_id}/auth-stats`（成员）。

（截图：用户授权页，见文档站）

用户授权页：只展示人数统计，不展示具体用户（图为还没有人授权时的空状态）。
