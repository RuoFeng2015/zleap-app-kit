# 数据库

「**数据库**」页管理当前应用所选环境（开发或生产）里的集合与文档：浏览和编辑文档、按条件筛选排序、查看结构、建索引、备份与恢复。

先记住三条边界：

1. **集合由 Manifest 声明**，控制台**不能新建集合**，也不能改结构；
2. 文档的浏览、筛选、新增、修改、删除覆盖该环境**所有使用者**的数据：改别人的文档会直接落到对方的数据里，
   新建的文档归你本人；集合的写入规则在控制台里不生效，但版本校验仍然生效。备份、恢复和唯一索引仍只作用于**你本人**的数据；
3. 开发和生产环境都能管理。在生产环境下页面顶部提示「这里是生产环境的数据：改动会立即影响线上用户。」
   环境不存在或已停用时显示「当前环境暂不开放数据访问。请选择活跃的开发环境。」

应用要通过 Cloud SDK 读写这些数据，还需要使用者在应用窗口的「**权限**」（「应用权限」对话框）里授权，
见 安装与卸载（文档站 /app-center/install）。

## 数据库开通状态

数据库就绪前，页面显示开通进度，而不是集合列表：

| 状态     | 标题                   | 说明                                                             | 按钮                   |
| -------- | ---------------------- | ---------------------------------------------------------------- | ---------------------- |
| 未开通   | **数据库尚未开通**     | 开通后即可创建集合和文档。                                       | 「开通数据库」「刷新」 |
| 开通中   | **正在开通开发数据库** | 通常 1 分钟内完成。页面每 3 秒自动检查一次，完成后直接显示数据。 | 无                     |
| 失败     | **数据库开通失败**     | 重试会继续原来的开通请求，不会重复创建资源。                     | 「重试开通」「刷新」   |
| 暂不可用 | **数据服务暂不可用**   | 基础服务恢复后可以重试。仍有问题时运行环境体检。                 | 「重试开通」「刷新」   |

标题下方是三步进度：「环境已创建」→「分配数据库资源」→「检查数据服务」。失败时会在出错的一步旁显示错误码。

- 数据库只有在**资源分配和数据服务检查都成功后**才显示就绪；
- 开发环境创建后会**自动开通**，一般不需要手动点「开通数据库」；
- 「开通数据库 / 重试开通」会**沿用服务端已有的开通请求 ID**，关掉窗口重开也不会重复开通。

开通请求的反馈：

| 提示                                                     | 含义 / 处理                                                |
| -------------------------------------------------------- | ---------------------------------------------------------- |
| 开通结果尚未确认，请检查原请求结果。（按钮「检查结果」） | 网络中断。点「检查结果」重新读取状态；确认前开通按钮被禁用 |
| 开通请求被拒绝，请检查发布者权限或联系管理员。           | 服务端明确拒绝                                             |

> **刚开通时短暂报错是正常的**（提示）
>
> 开通数据库时平台会重建数据服务，几秒内接口可能返回「资源未就绪」。页面会自动退避重试（最多 8 次），
> 不会直接显示「加载失败」。真正的失败显示「**无法读取开发数据，请检查权限和服务状态后重试。**」和「重试」按钮。

长时间不就绪时，到 概览运行环境体检（文档站 /console/workspace#环境体检），看卡在哪一层。

## 集合（Collection）

**集合**是一组采用相同数据规则的 JSON 文档，例如 `todos` 存放待办事项，类似关系库里的「表」。
概念见 核心概念 · 集合与文档（文档站 /guide/concepts#集合-collection-与文档-document）。

### 集合从哪来

集合写在 Manifest 的 `data` 里：

```json
"data": {
  "collections": ["notes"],
  "schemas": {
    "notes": {
      "type": "object",
      "properties": { "title": { "type": "string", "maxLength": 200 } },
      "required": ["title"],
      "additionalProperties": false
    }
  }
}
```

数据库就绪后，服务端**按声明自动创建**集合（包括私有 / 共享分区和记录规则）。
控制台只提供「**同步 Manifest 中的集合**」：它重新读取数据库状态，让服务端按声明补建缺失的集合。

还没有任何集合时，页面显示「**还没有集合**」，分两种情况：

| 情况                      | 说明文字                                                                                        | 操作                             |
| ------------------------- | ----------------------------------------------------------------------------------------------- | -------------------------------- |
| Manifest 声明了但还没建好 | Manifest 声明了 {n} 个集合，但还没有在开发环境中建好。点同步即可按声明创建。（列出集合键）      | 「**同步 Manifest 中的集合**」   |
| 没有声明                  | 集合由应用的 Manifest 声明，控制台不能单独新建。在 manifest.json 的 data 中声明后重新发布版本： | 无按钮，下方给出上面那段示例片段 |

> **控制台读的是你**当前安装**版本的声明**（注意）
>
> 「声明了哪些集合」来自你本人当前安装版本 Manifest 的 `data.schemas`。如果你还没安装这个应用，或者装的是旧版本，
> 就会显示「没有声明」。先在应用中心安装 / 更新到新版本，再回来同步。
> 另外，只列在 `data.collections`、没有写 `schemas` 的集合，不会出现在「未建好」的提示里（它们仍会由服务端按声明创建）。

### 集合列表

左侧是「**集合**」列表（标题旁是集合总数），每一项显示集合键和文档数（文档数可能只统计你本人的数据，与右侧列表的全体文档不一致时以列表为准）。

如果有声明了但还没建好的集合，列表底部提示「**未建好的声明集合：{集合键…}**」，并给出「同步 Manifest 中的集合」按钮。

右侧是选中集合的详情：

- 标题：集合键 + 数据归属标签：

  | 标签           | 含义                                                 | 怎么声明                                                               |
  | -------------- | ---------------------------------------------------- | ---------------------------------------------------------------------- |
  | **使用者隔离** | 私有集合：每个使用者在应用里只读写自己的文档（默认） | 什么都不用写                                                           |
  | **环境共享**   | 同一环境内的使用者共用一份数据                       | 列入 `data.shared_collections`，或 `policies.<键>.partition: "shared"` |

- 右上角「**备份与恢复**」按钮；
- 一行摘要：「{n} 条文档 · {m} 个字段 · 创建于 {日期}」；
- 三个标签页：「**文档**」「**结构**」（带字段数）「**索引**」（带索引数）。

> **控制台看到的是全体使用者的数据**（提示）
>
> 无论私有还是共享集合，控制台都列出该环境**所有使用者**的文档（编辑抽屉的副标题里能看到创建者）。
> 应用里通过 SDK 读到的范围仍按集合的私有 / 共享规则限定。

有写操作正在等待结果时，集合列表会被锁住，不能切换集合。

## 文档（Document）

**文档**是集合里的一条记录（一个 JSON 对象），**文档键**是它在集合里的唯一标识，例如 `note_001`。
每次保存文档版本号 +1，界面里写作 `v{n}`。

### 文档表格

「文档」标签页是一张按 Schema 渲染的表格：

- 第一列是「**文档键**」，最后一列是「**版本**」（`v{n}`）；
- 中间每列对应 Schema 里的一个字段，表头带类型符号，必填字段带「•」；
- 单元格按类型显示：日期显示为本地时间，数字带千分位，选项显示为标签，是/否显示「✓」，对象显示为 JSON 文本；
- 不加条件时按**创建时间倒序**，每页 20 条；底部「**第 {from}–{to} 条，共 {total} 条**」和翻页按钮。

字段类型由 Schema 推出：

| 界面类型 | Schema 写法                                               |
| -------- | --------------------------------------------------------- |
| 文本     | `"type": "string"`（`maxLength` ≤ 300 或未写）            |
| 长文本   | `"type": "string"` 且 `maxLength` > 300                   |
| 选项     | 带字符串 `enum`                                           |
| 数字     | `"type": "integer"` / `"number"`                          |
| 日期时间 | `"type": "integer"` + `"x-agentos-value-type": "date_ms"` |
| 是/否    | `"type": "boolean"`                                       |
| 对象     | 其他（对象、数组等）                                      |

> **翻页深度有上限**（注意）
>
> 服务端分页最多翻到约第 1000 条（列表 offset 与查询 skip 都 ≤ 1000）。超过的部分在控制台里翻不到，
> 要用筛选条件缩小范围，或「输入文档键直接打开」。

工具栏：

| 控件                                | 作用                                                            |
| ----------------------------------- | --------------------------------------------------------------- |
| 「**筛选**」                        | 按条件筛选，见下一节；按钮上的角标是生效的条件数                |
| 「输入文档键直接打开」+「**打开**」 | 按文档键直接读取一条文档；找不到时提示「没有找到文档「{key}」」 |
| 「**新建文档**」                    | 打开空白编辑抽屉                                                |

集合里还没有你的文档时显示「**这个集合还没有文档**」——「新建一条文档，或在应用里通过 Cloud SDK 写入后刷新。」

（截图：数据库文档视图，见文档站）

文档标签页：左侧集合列表，右侧文档表格、筛选、输入文档键直接打开、新建文档与备份入口。

### 筛选与排序

点「**筛选**」打开「**按条件筛选**」弹层：

- 每行一个条件：「字段」「条件」「值」，右侧 × 删除；
- 「**添加条件**」，最多 8 条，「同时满足全部条件」（AND）；
- 「**应用**」后才发起查询；「**清除筛选**」清空所有条件。

各类型可用的比较：

| 字段类型             | 可用条件                                                   |
| -------------------- | ---------------------------------------------------------- |
| 文本、数字、日期时间 | 等于、不等于、大于、大于等于、小于、小于等于、有值、没有值 |
| 选项、是/否、长文本  | 等于、不等于、有值、没有值                                 |
| 对象                 | 不能作为筛选字段                                           |

- 日期按**毫秒时间戳**比较，输入框里填的是本地时间；
- 值和字段类型对不上时，弹层提示「**有条件的值与字段类型不符，请检查标红的项**」，不会发请求。

**排序**：点表头切换「升序 → 降序 → 不排序」。可排序的类型：文本、数字、日期时间、选项、是/否（长文本、对象不能排序）。

有条件或排序时，表格改走数据面的条件查询（与应用里 `where().orderBy()` 走同一套查询能力），
工具栏显示「查询中…」或「**匹配 {n} 条**」。没有结果时显示「**没有符合条件的文档**」——「调整或清除筛选条件后再试。」

查询被数据面拒绝时有两种专门提示：

| 提示                                                                                                   | 原因                                                         | 操作                                                                                                       |
| ------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------- |
| **这个条件需要索引** —— 集合数据较多，没有索引时无法逐条扫描。给常用的查询字段建一个索引即可。         | `INDEX_REQUIRED`：数据量超过数据面的扫描上限，又没有可用索引 | 「**为 {字段} 建索引**」（跳到「索引」标签页并预选该字段）；推不出字段时是「**去建索引**」；或「清除筛选」 |
| **这个字段不能这样比较或排序** —— 大小比较和排序要求字段的值类型一致；文本字段需要在结构中声明为文本。 | `QUERY_TYPE_REQUIRED`：字段值类型不一致或未声明类型          | 「清除筛选」（同时清掉排序）                                                                               |

建议索引的字段取**第一条「等于 / 大于 / 大于等于 / 小于 / 小于等于」条件**的字段。只排序、没有比较条件时没有建议字段。

> **这是「你的数据量 + 索引」问题，不是平台故障**（提示）
>
> 应用里同样的查询也会因 `INDEX_REQUIRED` 被拒。给常用的筛选 / 排序字段建索引即可；
> 索引资格见 [索引](#索引)。

### 编辑抽屉

点表格的一行（或按回车）打开右侧编辑抽屉：

- 标题：文档键（新建时「新建文档」）；副标题「{集合} · v{版本} · {创建者}」（新建时「{集合} · 未保存」）；
- 右上角「**表单 / JSON**」切换；
- 底部：「**删除**」（仅已有文档）、未保存时的「● 未保存」、「**放弃更改**」、「**保存**」（新建时「**创建文档**」）。
  `Ctrl/⌘ + S` 也能保存。

**表单视图**按字段类型给出控件：选项用下拉、是/否用开关、长文本用多行框、日期用日期时间选择、数字用数字框；
有 `maxLength` 的文本显示「已输入 / 上限」计数。对象类型字段在表单里**只读**，要改请切到 JSON 视图。
集合没有 Schema（宽松模式，没有字段列表）时只有 JSON 视图。

新建文档时：

- 必须填「**文档键**」：「保存后不能修改。最多 128 字节，不能包含 / 和 \。」占位「例如 note_001」。
  不合法时提示「请填写不超过 128 字节、不含 / 和 \ 的文档键」（控制字符同样不允许）；
- 必填的日期字段默认填当前时间，必填的选项字段默认选第一个。

保存前控制台先做一次**本地预校验**（最终以服务端 strict 校验为准）：

| 提示                                 | 含义                              |
| ------------------------------------ | --------------------------------- |
| 必填                                 | 必填字段没填                      |
| 超出 {max} 字符上限                  | 文本超过 `maxLength`              |
| 格式不正确                           | 数字 / 日期字段填的不是数字       |
| {字段} 不在集合结构中                | 写了 Schema 里没有的字段          |
| 这些字段不在集合结构中，保存会被拒绝 | 汇总列出多余字段                  |
| JSON 格式不正确，或不是对象          | JSON 视图内容无法解析，或不是对象 |

JSON 视图提示「必须是 JSON 对象，字段需符合集合结构。」

保存成功显示「**已保存为 v{n}**」。

切换到另一条文档、或关闭抽屉时如果有未保存内容，会确认：

> **放弃当前未保存内容？**
>
> 切换文档会清除当前编辑内容。

### 版本冲突

保存和删除都带着你**读取时的版本号**提交。如果这条文档在别处（应用、其他窗口）已被更新，服务端拒绝写入，抽屉里显示：

> **这条文档已在其他地方更新**
>
> 你的修改还在，没有保存。先看看服务器上改了什么，再决定是否基于最新版本继续。

处理步骤：

1. 点「**对比最新版本**」：读取服务器上的最新版，下方显示逐字段对比（「服务器 v{n}」对「我的修改」，空值显示「（无）」，没有不同时「没有字段差异」）；
2. 点「**基于 v{n} 继续编辑**」：把版本基准换成服务器最新版，**你编辑框里的内容保持不变**；
3. 根据对比结果手动合并后，再点「保存」。

冲突处理期间「保存」和「删除」不可用。

> **「基于 v{n} 继续编辑」之后再保存，会用你的内容覆盖服务器版本**（注意）
>
> 它不会自动合并。如果服务器上别人改过的字段你想保留，请先按对比结果把它们抄进你的编辑内容，再保存。

### 删除文档

点抽屉底部「删除」，确认：

> **删除文档“{文档键}”？**
>
> 此操作将按当前版本软删除文档。其他端已更新时会拒绝删除。

**软删除**是打删除标记而不是立即物理抹除，便于审计。被删除的文档不再出现在列表和应用查询里。

### 写入结果反馈

| 提示                                                                                     | 含义                     | 怎么办                                               |
| ---------------------------------------------------------------------------------------- | ------------------------ | ---------------------------------------------------- |
| 已保存为 v{n}                                                                            | 成功                     | —                                                    |
| 这条文档已在其他地方更新                                                                 | 版本冲突                 | 见上文                                               |
| **请求被拒绝** —— 本地内容已保留。请检查字段是否符合结构，以及当前权限。                 | 被拒绝（如 Schema 不符） | 修正后重新保存                                       |
| **结果待确认** —— 网络中断，服务器可能已经处理。查询结果只读取原操作回执，不会重复写入。 | 结果未知                 | 点「**查询结果**」；需要排障时点「**复制操作编号**」 |

「结果待确认」期间不能再次保存，控制台也**不会自动重发**。「查询结果」只按原操作编号查回执；
**查不到回执不代表失败**，原请求可能还在执行，稍后再查。见 核心概念 · 结果未知（文档站 /guide/concepts#结果未知-commit-unknown）。

## 结构

「**结构**」标签页列出集合 Schema：

> **结构创建后不能修改** —— 严格模式：文档只能包含下面的字段。需要调整时，新建一个集合并迁移数据。

表格列：「字段」「类型」「必填」（必填 / 可选）「约束」（选项值、「最多 {n} 字符」、日期字段「按毫秒时间戳存储」）。
底部「**查看 JSON Schema 原文**」展开服务端保存的完整定义。

（截图：集合结构标签页，见文档站）

结构标签页：明确写出「结构创建后不能修改」，下面按字段列出类型、必填与约束。

> **新版本改 Schema 不会更新已有集合**（注意）
>
> 集合一旦建好，后续版本 Manifest 里改了它的 Schema 也**不会**应用上去；私有 / 共享分区也不能改。
> 需要改结构时，在 Manifest 里声明一个新集合并迁移数据。Schema 写法和限制见 [Manifest v2 配置](manifest.md)。

## 索引

**索引**为指定字段建立查询结构，让筛选和排序在数据量大时也能执行（避免 `INDEX_REQUIRED`）。

「**索引**」标签页左侧：

- 「**已创建的索引**」（`{n}/4`）：每行显示索引名、字段、「唯一」标签（若是）、「就绪」；
  没有时「还没有索引。给常用的查询或排序字段建索引，可以让应用查询更快。」；读不到时「暂时读不到已建索引，稍后刷新再看。」
- 「**字段能否建索引**」：逐个字段显示「可以」或原因：

  | 原因                         | 含义                                       |
  | ---------------------------- | ------------------------------------------ |
  | 不是必填字段                 | 字段不在 `required` 里                     |
  | 不是单个值                   | 对象 / 数组字段                            |
  | 文本上限 {max}，需不超过 191 | 文本 / 选项字段没写 `maxLength` 或超过 191 |

  即：只有 **strict Schema 中必填、非空的顶层标量字段**（数字、日期、是/否，或 `maxLength` ≤ 191 的文本 / 选项）能建索引。
  没有任何字段符合时提示「这个集合没有可以建索引的字段。索引字段需要是必填的数字、日期，或上限不超过 191 的文本。」

右侧「**新建索引**」：

1. 「**字段**」下拉（「只列出可以建索引的字段」）；从「这个条件需要索引」跳过来时已预选。
   如果建议的字段不能建索引，会提示「「{字段}」不能建索引：{原因}。可以换一个必填的数字、日期或短文本字段作为筛选条件。」
2. 开关「**同一用户下值不能重复**」：唯一索引。它只要求**你本人**的数据里不重复，不是全局唯一，不能用来做「全平台唯一的用户名」；
3. 点「**新建索引**」，确认「**为 {字段} 创建索引？**」：

   > 仅支持 strict 模型的必填非空顶层标量，字符串长度不超过 191。每集合最多 4 个索引；建立期间集合暂停访问，失败请继续原操作。

索引名自动生成为 `idx_<字段名小写>`（最长 32 个字符），不需要填写。每个集合**最多 4 个**索引，满了按钮不可用。

> **建索引期间集合暂停读写**（注意）
>
> 「建索引期间这个集合暂停读写，通常几秒钟。」此时应用对这个集合的读写会被拒绝。

请求没有得到确认时提示「**索引操作未确认，集合可能仍冻结。**」——「点「继续原操作」完成同一个请求。」
按钮变为「**继续原操作**」，会用**同一个请求 ID** 重试，不会建出第二个索引。这个待继续的请求只保存在当前页面里，关闭页面后需要重新读取索引列表确认状态。

## 备份与恢复

点集合标题右侧「**备份与恢复**」打开抽屉（副标题「开发环境 · 仅你本人的数据」，在生产环境下也显示这句，以实际所选环境为准）。
虽然入口在集合详情里，备份的范围是**当前环境中你本人的全部数据**，不是单个集合。

范围说明：

> 仅备份和恢复当前环境中你本人的数据。恢复前会自动保存当前快照，期间暂停数据读写。单次最多 1000 条记录、8 MiB。

| 区块 / 按钮                      | 作用                                       |
| -------------------------------- | ------------------------------------------ |
| 「创建备份」区的「**立即备份**」 | 为你本人的当前数据创建备份                 |
| 「**可恢复的备份**」列表         | 每行显示创建时间和大小；没有时「暂无备份」 |
| 每行的「**恢复到此**」           | 用这份备份替换当前数据                     |

两种操作都会先确认（标题「**创建当前数据备份**」/「**恢复所选备份**」）：

> 操作将短暂冻结本人的数据。恢复会替换此范围当前记录，不影响其他环境或用户，旧会话将失效。

> **恢复会替换当前数据**（危险）
>
> 「恢复到此」会用所选备份**替换**你本人在当前环境的全部记录，备份之后新增或修改的数据会被覆盖。
> 恢复前服务端会自动保存一份安全快照，但请确认选对了备份。恢复完成后旧的应用会话失效，需要重新打开应用。

### 进行中、继续与取消

维护操作有服务端持久的进度记录，**关掉页面后再打开也能看到未完成的操作**。未完成时抽屉顶部显示：

> **维护操作还没有完成**
>
> 操作尚未完成，数据可能仍冻结。可继续同一操作，或在恢复提交前安全取消。

按钮：「**继续原操作**」「**安全取消**」「**复制操作编号**」。有未完成操作时不能发起新的备份或恢复。

「安全取消」会确认：

> **取消当前维护操作？**
>
> 取消将结束尚未提交的维护并解除数据冻结。若恢复已经提交，取消会被拒绝，请继续原操作完成解冻。已保存的备份会保留。

结果提示：

| 提示                                                             | 含义                     |
| ---------------------------------------------------------------- | ------------------------ |
| 维护操作已完成，请重新打开应用会话。                             | 成功（**需要重开应用**） |
| 维护操作已取消，数据已解除冻结。请重新打开应用会话。             | 已取消                   |
| 维护请求已被拒绝，请检查权限、所选备份或重新读取服务状态后重试。 | 被拒绝                   |
| 维护结果尚未确认，请刷新读取服务状态。                           | 结果未知                 |

结果未知时控制台**不会自动再发起一次恢复**，而是查询原操作的状态；请用「继续原操作」推进同一个操作。

> **数据库备份不含文件**（注意）
>
> 数据库备份**不包含**文件存储；文件有自己的备份，见 文件存储（文档站 /console/storage）。文件恢复也**不会**回滚数据库，两者独立。

## 常见问题

### 页面一直是「正在开通开发数据库」

正常情况下 1 分钟内完成，页面会自动刷新。长时间不变时运行 环境体检（文档站 /console/workspace#环境体检）：
L0、L2–L4 失败属于平台侧问题，联系管理员。

### 没有集合，也没有「同步」按钮

页面显示的是「没有声明」那种情况：你当前安装的版本 Manifest 里没有 `data.schemas`。
在 Manifest 里声明集合，重新打包上传，并在应用中心把安装更新到新版本，再回来同步。

### 想新建集合 / 改集合结构

控制台做不到。新建集合要在 Manifest 的 `data` 里声明并发布新版本；已有集合的结构和分区不能改，只能新建集合并迁移数据。

### 应用写入报 `SCHEMA_INVALID`

文档和集合 Schema 对不上——这是你的数据或代码问题，不是权限问题。检查：

- 是否漏了 `required` 里的字段；
- 字段类型是否正确，尤其是日期：声明为 `date_ms` 的字段要传 `Date` 对象，不能传 `Date.now()`；
- 是否写了 Schema 里没声明的字段（缺省 `additionalProperties` 按 `false` 处理）。

用控制台的表单视图新建一条文档，能帮你快速确认 Schema 期望的形状。

### 应用读写报 `SCOPE_FORBIDDEN`

使用者没在应用窗口里授权数据读写。点应用窗口顶部的「**权限**」，勾选「读取本人的应用数据」「修改本人的应用数据」后「保存并重新加载」。
见 安装与卸载（文档站 /app-center/install）。

### 应用查询报 `INDEX_REQUIRED`

集合数据量超过扫描上限，而查询条件 / 排序字段没有索引。到「索引」标签页给对应字段建索引；
字段不满足索引资格时，改用一个必填的数字、日期或短文本字段做条件。

### 应用里看不到别人的数据

控制台能看到所有使用者的文档，但应用里私有集合只返回当前使用者自己的文档，这是设计如此。需要用户之间共享数据，
在 Manifest 里把集合声明为共享（`shared_collections`）。共享集合**环境内所有人可见，不要放隐私数据**。
